# 架构决策记录 v0.1（2026-10-26）

## ADR-1 复用策略：借格式、借执行层、不 fork
- **决定**：不以任何现成工具为代码底座。借 Backlog.md 的"任务即仓库里的 Markdown + frontmatter"格式思路；执行层直接用 Claude 桌面版的会话与 worktree（不造会话启动器）；验收层用本机 Codex CLI；自己只写"版本列车"这一层。
- **理由**：竞品盘点 20+ 工具无一把"版本"当一等概念；Backlog.md 若作依赖只带来英文看板与不含绑定字段的 schema，收益小于适配成本；Vibe Kanban 公司已关停。用户已深度绑定桌面版（280 条会话、默认开 worktree）。
- **代价**：看板、CLI、MCP 自己写；但范围被压到"对账 + 预约 + 合并单"，可控。
- **后门**：台账保持 Markdown/YAML 人可读，必要时可导出为 Backlog.md 兼容格式。

## ADR-2 技术栈：Bun + TypeScript 单仓库，Claude Code plugin 形态交付
- 运行时 **Bun 1.3**（已装；TS 原生、启动快适合 hook、`bun:sqlite` 内置、`bun build --compile` 可出单文件 CLI）。Node 22 作为兼容回退。
- CLI：commander。MCP：`@modelcontextprotocol/sdk`（stdio）。看板：Hono 本机服务 + Preact（Bun 打包成单文件，无 CDN 依赖，离线可用）。
- 交付：同一仓库同时是 Claude Code **plugin**（`.claude-plugin/plugin.json` + `skills/heliu` + `hooks/hooks.json` + `.mcp.json` + `bin/heliu`），一条命令装进任何项目；二期做桌面应用 mod pane（桌面内置 CLI 2.1.308 ≥ 2.1.287 满足要求）。

## ADR-3 数据落点：承诺进仓库、事实进缓存、绝不放 iCloud 数据库
- **项目注册表**：`~/Library/Application Support/heliu/projects/<name>/project.yaml`（项目 → 多仓库路径、主线分支、集成分支、远端名、是否 iCloud）。
- **台账（承诺）**：主仓库 `<repo>/.heliu/`：`milestones.yaml`、`features/*.md`（frontmatter：id、title、status、milestone、bindings[{repo,branch,worktree,session}]、acceptance、rolled_from）、`releases/vX.md`（合并单与执行记录）。纯文本、可提交。
- **索引缓存（事实）**：`~/Library/Application Support/heliu/cache/<name>.sqlite`，可删可重建。
- **桌面应用会话**：只读解析 `~/Library/Application Support/Claude/claude-code-sessions/*/*/local_*.json`（title、cwd、worktreeName、worktreePath、branch、sourceBranch、prs、postTurnSummary、isArchived、lastActivityAt、spawnedFrom）与 `git-worktrees.json`（worktrees{name,path,branch,sourceBranch,leasedBy,uncleanSince}）。字段内部无文档 → 容错、只读。

## ADR-4 git 访问纪律（iCloud 现场教训）
- 只用对象库命令：`for-each-ref`、`rev-list --count A..B`、`merge-base --is-ancestor`、`merge-tree --write-tree`（试合，不碰工作区）、`worktree list --porcelain`、`log -1 --format`。
- 任何可能触碰工作区的命令（`status`）：`GIT_OPTIONAL_LOCKS=0` + 超时（默认 8s），超时标"未知/需下载"，不卡死、不误判。
- **绝不自动** `push`、`fetch`（远端对比用已有的 `refs/remotes/*`，另提供显式 `heliu fetch`）、`worktree remove`、`branch -d`、`checkout`。合并执行（M4）只在用户确认合并单后、在集成分支的独立 worktree 里进行。
- **自更新例外（F-0004，2026-11-04）**：合流**自己的代码目录**可以按 GitHub 主线更新。检查只用 `git ls-remote`，不写引用；只有用户在看板点「更新」并确认、或运行 `heliu update --yes` 后，才 `fetch` 并 `merge --ff-only`。前提是代码目录在 main 上、跟踪文件没有改动、本机 main 没有 GitHub 上没有的提交，任何一条查不清都不做。代码在 `src/core/selfupdate.ts`，不经过 `src/core/git.ts` 的白名单，那个白名单不放宽。合流代码目录同时登记成被管理项目时，那边的对账照旧只读。

## ADR-5 "已合并"三档 + 验收四档
- 合并状态：`进主线` / `进集成分支` / `独立未合并`，另加 `内容等价`（diff 为空但历史不同）。
- 验收档位独立字段：`已合并 / 已构建 / 宿主测试 / 实机通过`，合并不自动提升。

## ADR-6 零额外动作的登记靠 hooks
- `SessionStart`：注入"你在 <仓库>/<分支>，对应功能 <X>，预约 <vY>，落后主线 N；若无功能卡请调用 heliu.feature.add 登记"。
- `Stop`/`SessionEnd`：回写最后活动、状态摘要。
- `WorktreeCreate`：以会话标题为名建功能卡草稿，默认预约"下一版"。
- hooks 必须 <300ms 返回（Bun 启动）；失败静默，不阻塞会话。

## ADR-7 模型分工与验收闸门（用户规则）
- Fable 5.1：规划、产品定义、每个里程碑的最终验收。
- Opus 5.5：全部编码、检索类子代理（`model: "opus"`）。
- 每个里程碑：Fable 验收通过 → `codex exec -s read-only --output-schema` 以普通用户视角走验收口径 → 最多 3 轮 → 记录到 `docs/04-验收记录/M<N>.md`，超 3 轮记录问题继续推进。
