# M2 任务卡：台账（承诺层）+ MCP server + hooks + Skill

## 目标
让"开一个会话随口说做个 X"自动变成一张预约到下一版的功能卡；让任何 Claude/Codex 会话都能一句话查"vX 还欠什么"。在 M1 只读内核之上加承诺层与三种调用面。

## 台账格式（`<ledger>/`，默认 `<主仓库>/.heliu/`，project.yaml 里 `ledger:` 可覆盖）
- `milestones.yaml`
  ```yaml
  milestones:
    - id: v1.2
      title: 固件 1.1 + App 1.0 收口
      status: 规划中        # 规划中 | 冻结 | 合并中 | 已发布
      target_date: 2026-11-05   # 可空
      integration_branch: claude/merge-features-refactor-143693   # 可空，默认用 project.yaml 的 integration
      notes: ""
  ```
  特殊别名 `next`（"下一版"）= 第一个 `规划中` 的里程碑；若没有，自动创建 `vNext`（可改名）。
- `features/F-0001-<slug>.md`
  ```yaml
  ---
  id: F-0001
  title: 让背夹支持 X
  status: 开发中      # 想法 | 开发中 | 待合并 | 已合入 | 已进主线 | 已发布 | 已放弃
  milestone: v1.2     # 或 next；null = 未预约
  acceptance: 未      # 未 | 已合并 | 已构建 | 宿主测试 | 实机通过
  bindings:
    - repo: docs
      branch: claude/xxx-123456
      worktree: /abs/path            # 可空
      session: local_…               # 可空
      pr: 3                          # 可空
  rolled_from: []     # 顺延记录 ["v1.1"]
  source: session     # session | cli | mcp | hook
  created: 2026-10-26
  updated: 2026-10-26
  ---
  正文：一句话需求、备注、验收证据链接。
  ```
- 规则：**台账只存 git 里没有的东西**（承诺、绑定、验收档位、顺延）。领先/落后/冲突/最后活动等全部由 M1 对账实时派生，不落盘。

## 核心操作（`src/core/ledger.ts`）
`init(project)`, `feature.add(title,{milestone='next', bindings, body, source})`, `feature.reserve(id, milestone)`, `feature.bind(id, binding)`, `feature.setStatus/setAcceptance`, `feature.list({milestone,status})`, `milestone.add/list/freeze`, `milestone.todo(id)` = 预约到该版且未 `已合入` 的功能，按对账结果分组：可合并 / 有冲突 / 落后需同步 / 开发中 / 阻塞-等你回答 / 停滞 ≥7 天 / 无绑定。
`sync(project,{dryRun})`：**自动草稿**——扫描本项目桌面会话与分支，凡 worktree 分支无功能卡且非已进主线者，用会话标题（无标题则 M1 标签）建 `想法/开发中` 草稿卡，预约 `next`，`source: hook|sync`；同一分支只建一次；dry-run 只列不写。

## CLI 增量
`heliu init`、`heliu feature add|list|reserve|bind|status|accept`、`heliu milestone add|list|todo|freeze`、`heliu sync [--dry-run]`、`heliu whereami [--cwd]`、`heliu mcp`。
中文别名：`heliu 新点子 "<标题>" [--预约 v1.2]`、`heliu 待办 [v1.2|下一版]`、`heliu 预约 F-0003 v1.3`、`heliu 我在哪`。

## MCP server（`heliu mcp`，stdio，`@modelcontextprotocol/sdk`）
工具（全部可带 `cwd` 参数，因为 MCP 进程不知道 worktree 路径；缺省用 `CLAUDE_PROJECT_DIR`）：
`heliu_whereami`、`heliu_status`、`heliu_sessions`、`heliu_hygiene`、`heliu_feature_add`、`heliu_feature_reserve`、`heliu_feature_bind`、`heliu_feature_set_status`、`heliu_milestone_todo`、`heliu_milestone_list`、`heliu_sync`。描述用中文，示例用口语（"把这个预约到 1.2"）。返回 ≤10k token，大表自动截断并提示用 `--json` CLI。

## Hooks（plugin `hooks/hooks.json` + `bin/heliu-hook`，必须 <300ms，失败静默 exit 0）
- `SessionStart`：读 stdin {session_id, cwd} → `whereami` → `hookSpecificOutput.additionalContext`（中文）：
  "【合流】你在 <仓库标签>/<分支>，功能卡 F-0012『…』预约 v1.2；落后主线 N 提交、落后集成分支 M。" 若无功能卡："本分支暂无功能卡；若本会话在做新功能，请在明确需求后调用 heliu_feature_add 登记（标题用用户的一句话），否则忽略。"
- `Stop`：把 session_id → 最后活动写入缓存 sqlite（不写台账）。
- `WorktreeCreate`：记录 {name, cwd, time} 到缓存，供 `sync` 建草稿时标 `source: hook`。

## Skill（plugin `skills/heliu/SKILL.md`，主控会话用）
教主会话：① 用 MCP 工具答"v1.2 还欠什么/这个预约到哪"；② 用桌面应用自带 `start_session` 为某功能卡开新会话（先 `heliu_feature_add` 再开会话并 `heliu_feature_bind` 回写 session id）；③ `heliu_sync` 后把草稿卡逐条报给用户确认改名/预约；④ 永不 push、不删分支。

## Plugin 骨架
`.claude-plugin/plugin.json`（name heliu）、根 `.mcp.json`（heliu mcp）、`hooks/hooks.json`、`skills/heliu/SKILL.md`、`bin/heliu`、`bin/heliu-hook`。本地加载：`claude --plugin-dir <本仓库>`；或 marketplace。

## 验收（Fable）
1. fixture 仓库：`heliu init` → `heliu 新点子 "X"` → `heliu 待办 下一版` 列出 X；`bun test` 全绿。
2. MCP：用 bun 脚本发 JSON-RPC `initialize`/`tools/list`/`tools/call heliu_feature_add`，返回正确。
3. hook：`echo '{"session_id":"t","cwd":"<fixture worktree>","hook_event_name":"SessionStart"}' | bin/heliu-hook` 输出含中文 additionalContext，耗时 <300ms（`time` 测三次）。
4. 真实数据只读演练：磁吸背夹 project.yaml 的 `ledger` 先指向 `~/Library/Application Support/heliu/projects/磁吸背夹/ledger/`（**M2 不写进磁吸背夹仓库**），`heliu sync --project 磁吸背夹 --dry-run` 列出 ≥15 条草稿；去掉 dry-run 后 `heliu 待办 下一版` 分组正确、阻塞项带 needs_action 文案。
5. 三个被管理仓库零写入（同 M1 方法）。
