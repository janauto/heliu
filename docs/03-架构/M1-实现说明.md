# M1 实现说明：对账单只读内核 + CLI（2026-10-26）

> 对应 `M1-任务卡.md`。实现：Opus 5.5；验收：Fable。全程未改动任何被管理仓库。

## 1. 目录结构
```

src/core/git.ts           只读 git 层：子命令+参数白名单、8s 超时、并发≤4、GIT_OPTIONAL_LOCKS=0、sandbox-exec 写保护
src/core/paths.ts         数据位置（HELIU_HOME / HELIU_CLAUDE_APP_DIR / HELIU_CLAUDE_HOME 可覆盖）
src/core/project.ts       注册表 project.yaml（zod 校验；<repo>/.heliu/project.yaml 优先；自动识别当前项目）
src/core/branches.ts      for-each-ref、--merged 三档、ahead/behind、首条独有提交、merge-tree 预检
src/core/worktrees.ts     worktree list --porcelain、.git/worktrees 只 readdir/stat、脏检查
src/core/sessions.ts      桌面会话 / git-worktrees.json / 运行中会话，zod 宽松解析

src/core/doctor.ts        环境自检
src/cli/{index,render,table}.ts   commander 命令、中文渲染、按显示宽度对齐
tests/                    bun test：临时 fixture 仓库 + 会话 JSON fixture（含缺字段/类型错误/坏文件）
examples/磁吸背夹.project.yaml    注册表副本（正本在 ~/Library/Application Support/heliu/projects/磁吸背夹/）
```

## 2. 命令示例
```bash
bun install                                   # node_modules → node_modules.nosync（iCloud 不同步）
bun run bin/heliu doctor                      # git≥2.38、bun、数据目录、注册表、每仓库可达、iCloud 警告
bun run bin/heliu status --project 磁吸背夹     # 默认「行动摘要」：健康条 + 每仓库四组
bun run bin/heliu status --full               # 全部分支长表（标签|分支|worktree|会话|主线↑/↓|集成↑/↓|合并状态|最后提交）
bun run bin/heliu status --precheck --json | jq '.data.repos[].branches[].precheck'
bun run bin/heliu branches --repo docs --state in_integration
bun run bin/heliu sessions                    # 默认只列「等你处理」「运行中」，待办文案全文折行
bun run bin/heliu sessions --all              # 再追加 待验收/已完成/已归档 的表格
bun run bin/heliu hygiene                     # 只报告，不动手
bun run bin/heliu project add <path> [--name 项目] [--integration 分支]
bun run bin/heliu project list
```
全局选项：`--project`（缺省按当前目录/worktree 自动识别，注册表只有一个项目时直接用）、`--json`、`--precheck`、`--dirty`、`--timeout <ms>`、`--wide`（表格与单行条目不截断）。

`status` 默认的四组（第 2 轮按 Codex 验收反馈改）：
- ① **等你处理**：关联会话状态为「等你」的分支（含已进主线的），`needs_action` 全文按终端宽度折行，缺失时用 `status_detail`。
- ② **独立未合并**：未进主线也未进集成分支的功能分支：标签 · 分支 · 主线↑/↓ · 集成↑/↓ · 最后提交（无集成分支的仓库不显示集成列）。
- ③ **已进集成分支待回主线**：只给计数 + 「集成分支领先主线 N，M 天未并回」。
- ④ **落后需同步**：②中相对集成分支（无集成分支则相对主线）落后 >0 的，给计数和落后最多的 5 条。已进主线的分支不算（已无需同步）。

顶部图例「↑领先 ↓落后（提交数）· worktree 数不含主目录 · 工作区检查数含主目录」；健康条里「本地无远端引用 N」只基于本地已有 `refs/remotes`，末尾括注「（远端对比基于本地已有引用，未 fetch）」（JSON 字段名 `neverPushed`/`pushed` 沿用 v1，注释已改）。

## 3. 关键设计
- **合并三档**：`for-each-ref --merged=<主线>` 与 `--merged=<集成>` 两次批量调用；ahead/behind 用 `%(ahead-behind:)`（git≥2.41，否则逐分支 `rev-list --left-right --count`）。集成分支自身单列「集成分支·未并回」。
- **标签**：会话标题 > 首条独有提交（`log --reverse --first-parent --no-merges <分支> --not <主线> <不含本分支的其他分支>`）> 改动最多的一级目录 > 末次提交 > 分支名。排除「不含本分支的其他分支」是因为固件仓 `feat/aios-*` 共用一段基础提交，只看 `main..branch` 会得到同一个标签。
- **会话关联**：归属看 `realpath(originCwd/cwd/worktreePath)` 落在哪个仓库根或 worktree（取最深）；分支关联按 `branch` 字段（强）> `writtenBranches`（「路径\0分支」）> 仅当 `branch` 为空时按 cwd 所在 worktree（弱，目录会被复用）。同强度未归档优先、最后活动倒序。运行态取 `~/.claude/sessions/<pid>.json` 且 `kill(pid,0)` 存活。
- **零写入的三道保证**：①白名单（含参数级：`branch` 仅 `--list`、`config` 仅读、`symbolic-ref` 仅单参数、`worktree` 仅 `list`、禁 `--output`）；②`--no-optional-locks` + `GIT_OPTIONAL_LOCKS=0` + `core.fsmonitor=false` + `gc.auto=0`；③macOS 上每条 git 都包在 `sandbox-exec` 里对仓库根、common dir、外置 worktree `deny file-write*`（路径写入 NFC/NFD 两种形式）。
- **merge-tree 的坑（实测）**：`--write-tree` 写出已存在的树时，git 会 `utime` 刷新**真实对象库里已有的 pack/松散对象**（fixture 上复现：pack mtime 被改）。对 iCloud 仓这意味着可能触发大 pack 重新上传。做法：`GIT_OBJECT_DIRECTORY` 指向临时隔离区、真实对象库作 alternates 只读；再叠加沙箱让 `utime` 失败，git 退而把对象写进隔离区。沙箱不可用时直接拒绝预检。
- **iCloud**：脏检查默认跳过（`--dirty` 才做），`.git/worktrees/*` 只 readdir/stat 不读内容（stat 不触发下载）；超时记「未知」不误判。

## 5. 取舍与已知限制
- **未在真实 iCloud 仓上跑 `--dirty`**：会触发 dataless 文件下载；超时→未知的路径由单测覆盖。脏检查用 `status --porcelain -uno`，**不统计未跟踪文件**（调研里主目录 59 条未跟踪不会出现）。
- **目录名≠分支名只查桌面端创建的 worktree**（`.claude/worktrees/` 下或登记在 `git-worktrees.json`）；固件/App 仓的兄弟目录命名（`esp_claw-aios-a1`）不按此规则报。
- 「内容等价」（ADR-5 第四档）只在 `--precheck` 时给出（试合树 = 目标树），默认三档。
- 集成分支无会话时标签取改动最多的目录；两个分支指向同一提交时标签必然相同。
- `sandbox-exec` 是 macOS 专有且被 Apple 标为弃用；不可用时（或 `HELIU_NO_SANDBOX=1`）其余命令仍受白名单 + 可选锁保护，但拒绝 `--precheck`。
- 运行中会话只用 `kill(pid,0)` 判活，未防 pid 复用；会话字段无官方文档，桌面端改格式时逐字段降级为缺失。
- Bun 1.3.4 的 `Bun.write(Bun.stdout)` 在管道满时会从头重写（实测 >64KB 的 `--json | jq` 损坏），已改为按字节偏移 `writeSync` 循环。
- 未做：`heliu fetch`（ADR-4 规定显式命令，M1 不需要）、SQLite 索引缓存（ADR-3，M2 起）、台账/MCP/hooks（M2）。
