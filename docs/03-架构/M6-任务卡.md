# M6 任务卡：图形化上手入口（看板升级为可操作的起点）

## 为什么
用户原话："搭建一个图形化的可操作界面，让我可以快速入手这个项目。"
现状：看板能看、能拖卡改预约，但**上手的每一步都在终端**——启动看板、环境自检、接入项目、把现有分支登记成卡、切换项目。看板启动时还绑死一个项目，多个项目时不加 `--project` 直接报错。

## 不另起桌面应用
ADR-2 已定：看板（本机 Web）就是 GUI 载体。M6 只把它从"对账单"升级成"上手入口"。

## 交付
1. **多项目**：服务端加项目中枢（项目名 → BoardService），所有项目级接口支持 `?project=`。`heliu board` 不带参数且识别不出项目时，照常启动，页面里选项目。
2. **「开始」页**（新的第一个页签）：五步引导。
   - ① 环境检查：`runDoctor` 结果分组显示；默认跳过无头 claude 探测，另有「完整检查」按钮（约 20 秒）。
   - ② 接入项目：已注册项目卡片（打开 / 再加一个仓库）+ 接入向导（粘贴路径 → 只读检测 → 选集成分支、改名 → 确认接入）。台账一律放 heliu 数据目录，GUI 不提供 `--ledger repo`。
   - ③ 把现有分支登记成卡：sync 预览 → 确认登记。
   - ④ 开始日常使用：就地登记新点子；跳到版本列 / 合并预演；可复制的"在 Claude 会话里怎么说"。
   - ⑤ 终端命令：当前项目的合并、演练、回滚命令，带复制按钮。
3. **顶栏项目切换**：下拉切换项目，记住上次选择。
4. **双击启动**：仓库根 `合流看板.command`。看板已在运行时直接打开浏览器，不报端口占用。
5. 新接口：`GET /api/projects`、`GET /api/doctor`、`POST /api/projects/detect`（只读）、`POST /api/projects`（只写注册表 + 台账）。

## 非目标（明确不做）
- GUI 不执行合并、不演练、不回滚：沿用"看板只预演，执行在终端输入 yes"的约定，页面给出可复制命令。
- GUI 不删项目、不改项目名、不把台账放进仓库。

## 硬约束
- 新写接口沿用三道防护：只听 127.0.0.1、Host 校验、写接口只收 JSON。
- 检测走 `detectRepo`（git 白名单），接入走 `addRepoToProject` + `Ledger.init`。被管理仓库零写入。
- 现有接口不带 `?project=` 时行为不变（测试全部保持通过）。

## 验收
1. `bun test` + typecheck 全绿；新增测试：项目列表、`?project=` 路由、无项目时的友好报错、检测不写任何文件、接入只写 HELIU_HOME 且仓库零写入、doctor 接口。
2. 内置浏览器实测：首次打开落在「开始」；向导接入一个临时仓库并登记草稿卡；顶栏切换项目；375px 可读。
3. 双击启动脚本：看板未运行时启动并打开；已运行时直接打开。
4. Codex 以新手视角验收（`scripts/codex-accept.sh M6 1 --ref <提交> --serve <端口>`），≤3 轮。
