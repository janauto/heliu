## 2. 启动
```bash
bun run bin/heliu board --project 磁吸背夹              # 默认端口 7788，启动后用 open 打开浏览器
bun run bin/heliu board --project 磁吸背夹 --port 7799 --no-open
```
启动输出：地址（`http://127.0.0.1:<端口>/`）、是否重新打包与产物大小；Ctrl+C 退出（命令在服务停止前不返回，避免 main.ts 的 `process.exit`）。端口被占用给中文提示（退出码 2）。启动后后台预热两次扫描（不预检 / 预检），打开页面时直接命中缓存。

## 3. API（全部 JSON；外壳 = `JsonEnvelope` + `meta{scannedAt, scanMs, cached, precheck}`；错误 `{error}`：台账/项目错误 400，其他 500）
| 方法 · 路径 | 说明 | 写 |
|---|---|---|
| GET `/api/status[?precheck=1][&fresh=1]` | `ReconcileReport`（M1 原样）；按「项目 × 是否预检」缓存 20 s；`fresh=1` 跳过缓存 | 否 |
| GET `/api/sessions` | `{total, sessions: SessionView[]}`（同 `heliu sessions --json`） | 否 |
| GET `/api/hygiene` | 每仓库四类（待清理 worktree / 目录名≠分支名 / 孤儿条目与锁文件 / iCloud 冲突副本与主目录）+ `suggestion` 命令文本 | 否 |
| GET `/api/milestones` | `{milestones, next}` | 否 |
| GET `/api/features[?milestone=][&precheck=0]` | 版本列：列（里程碑按 yaml 顺序 + 未预约 + 已发布）、列头计数、卡片（灯色/下一步/多标签/绑定事实）；默认预检 | 否 |
| GET `/api/features/:id/baseline` | 同步基线（预演）：主线/集成分支 → 本分支的落后数与冲突文件 | 否 |
| GET `/api/todo?milestone=[&precheck=1]` | M2 `groupTodo` 原样结果（含「尚无独有提交」判定，与 `heliu 待办` 同一套函数） | 否 |
| GET `/api/overview[?precheck=1]` | 现在最该做的（复用 M1 `topActions`，CLI 指引换成页面名）、一眼条数字、各版本计数、下一版 | 否 |
| GET `/api/release/preview?milestone=` | 合并预演（只读，总是预检）：顺序、三档状态、冲突文件、建议动作、预计顺延、台账状态建议、预演时主线/集成分支 sha；第 2 轮起多一档「未能试合」 | 否 |
| POST `/api/features` `{title, milestone?}` | 新点子（默认下一版；`null` = 不预约；source=board） | 台账 |
| PATCH `/api/features/:id` `{milestone?, title?, status?}` | 改预约（不存在的版本按 M2 规则自动建「规划中」）/ 改名 / 改状态 | 台账 |
| POST `/api/sync` `{dry_run?}` | M2 `syncLedger`（复用缓存的对账结果） | 台账 |
| POST `/api/release/plan` `{milestone}` | 预演写成 `<台账>/releases/<里程碑>.md` 草稿；已有草稿先备份到 `releases/.history/`；非「草稿」状态拒绝覆盖；**不执行合并** | 台账 |

安全：只监听 127.0.0.1；Host 头必须是 127.0.0.1 / localhost / [::1]（防 DNS rebinding，否则 403）；写接口只收 `application/json`（跨站表单发不出，否则 415）。

## 4. 页面（单页，顶部页签；每 30 s 自动刷新 + 刷新按钮；右上角「数据时间 HH:MM:SS · 用时 x.xs」）
- **顶部固定一行**：「下一版 = vNext（规划中）· 冲突：已检查 HH:MM:SS（重新检查）/ 未检查（点击检查）· 自动顺延：当前版本尚未实现，M4 提供」。页面打开后自动试合一次，之后自动刷新都带预检；「重新检查」= `/api/status?precheck=1&fresh=1`。用户不必记 `--precheck`。
- **一眼条**（每页可见）：各仓库「集成分支 N 天未并回（领先 M）」（≥3 天红）· 本地无远端引用 N · 等你处理 N 个会话。
- **总览**：现在最该做的（≤3 句，箭头前事实、箭头后建议）· 各版本「还欠 N · 可合 a · 冲突 b · 等你 c」· 每仓库健康卡（主线 vs 远端、集成分支、无远端引用、worktree 脏/未知/未检查、已进主线、卫生），每个数字旁一行中文解释。
- **版本列**：列头同上；列内按 M2 分组小标题（组名取自 `TODO_GROUP_DEFS`，可合并再按「已进主线 / 已进集成分支 / 试合无冲突」细分）。卡片默认只突出：灯色 + 组名、标题、**下一步一句话**（「等你回答：<needs_action 原文>」「需解冲突：试合到 X 有 N 个文件冲突」「可合并：试合到 X 无冲突…」「需同步基线 ↓102」）、**次要标签**（等你 / 冲突 N 文件 / 落后 ↓N / 停滞 N 天 / 尚无提交，与主分组重复的不再列）。「已合入 · 待确认台账」（M2 给了改状态建议）是单独样式（绿底虚线框）并直接带「标为已合入 / 标为已进主线」按钮。展开态：分支（随机名显示标签、悬停看原名）、主线↑↓/集成↑↓ 与解释、目录、会话、复制分支名、打开会话（`claude://` 链接）/ 复制会话 ID、改预约（下拉，含新版本）、改名、标记放弃、同步基线（预演）。**拖卡片到另一列 = 改预约**（HTML5 DnD；冻结/合并中/已发布列不可放）。另有「新点子」输入框与「把现有分支登记成卡（先预览）」。
- **卫生**：每仓库四类，每条附建议命令（只读命令优先；会改东西的写明「确认后」、不带 --force）与复制按钮。
- **会话**：等你（needs_action 全文 + 最后活动）/ 运行中 / 已完成（含待验收）/ 已归档 / 无状态记录（如实单列，不算「已完成」）。
- **合并预演**：醒目横幅「仅预演，不会执行合并（M4）」；选里程碑 → 计数 → 表格（顺序、功能、分支、三档状态、试合冲突文件数（点开看文件名）、建议动作）→ 预计顺延 → 台账状态建议 → 「生成合并单草稿」显示写入路径。顺序：已进集成（跳过）→ 试合无冲突（合入）→ 有冲突（冲突少的在前，需解冲突）→ 未完成（等你回答/开发中/尚未关联开发分支，顺延）；分档直接取 M2 分组（与 `heliu 待办 --precheck` 一致）。
- 375 px：列纵向堆叠、表格变卡片、顶栏不再吸顶；浅/深色随 `prefers-color-scheme`；系统字体栈。

合并单草稿格式：frontmatter（`heliu: release-plan`、`status: 草稿`、各仓库 `main_sha/integration_sha`、逐条 `order/feature/tier/action/decision/bindings{repo,branch,sha,merged_state,target,conflict_files,conflicts}`、`deferred`）+ 人读表（同一份内容，不写 `- [ ]` 复选框）。默认决定：已进集成 = 并入；无冲突且台账「待合并」= 并入，台账还是「开发中」= 待定；有冲突 = 待定；未完成 = 顺延（M4 可扩展「等它」）。

## 5. 打包机制
`runBoard` 启动时调 `ensureWebBuild()`：`dist/web/.build-stamp` 不存在、产物缺失、或 `web/` 下任一文件 mtime 更新 → `Bun.build`（entry `web/main.tsx`，minify，target browser）+ 复制 `index.html`、`styles.css→app.css`。无 CDN、无外链字体，离线可用；`dist/` 已 gitignore。产物：**app.js 48.0 KB（gzip 17.0 KB）· app.css 13.1 KB（gzip 3.7 KB）· index.html 0.5 KB**，打包 3–7 ms。

## 8. 已知限制与取舍
- **浏览器截图由验收方完成**。我只在桌面应用内置浏览器里做了目视自查（深色桌面宽度、浅色 375 px），未留截图。
- **会话链接**：真实会话 JSON 里没有 `claude://` 字段（全量 grep 为空），也没有自造链接；此时「打开会话」置灰并提供「复制会话 ID」。字段一旦出现（正则取 JSON 中第一个 `claude://…`）按钮自动可用。
- 拖拽是 HTML5 DnD，触屏上不可用；手机上用卡片展开态的「改预约」下拉。
- 版本列默认预检（灯色要分出红灯）；首次打开若缓存未热，会先显示不带冲突的结果并标「冲突：检查中…」，完成后自动换成预检结果。
- 「已发布」列只收台账状态为已发布、或所属里程碑为已发布的卡（磁吸背夹目前为空）；已放弃的卡不显示，只计数。
- 卡片只显示每个绑定分支的主会话；同一分支的其他会话在「会话」页。
- 「等你处理」一眼条数字按会话计（17），列头「等你」按功能卡计（11），两处口径在页面上分别写明。
- 看板一次只服务一个项目；`dist/` 在本仓库（iCloud）里，体积 <70 KB、可随时重建。
- 合并单草稿只覆盖「草稿」状态的同名文件（旧稿进 `.history/`）；执行、顺延、tag 均留给 M4。

## 9. 第 2 轮：试合失败三态（Codex 第 1 轮反馈）
**问题**：建不了写保护沙箱的环境里（Codex 沙箱，`sandbox-exec` 不能嵌套），36 张卡的绑定带 `precheckError`，但版本汇总仍返回「冲突 0、precheck=true」，前端显示「已检查」；预演还把它们归进「未完成 → 顺延」。没得到结果被说成了「没有冲突」。
**改法**（M1/M2 判定语义不变，分组照旧，只加事实字段与汇总）：
- 绑定级三态 `precheckStateOf`（`src/core/todo.ts`）：`checked`（有结果）/ `failed`（请求了没结果：沙箱、超时、出错）/ `skipped`（没请求）；不需要试合（已进主线/集成分支、分支不存在）为 null。`TodoBinding` 追加 `precheck`、`precheckError`，`CardBinding`/`ReleaseBinding` 追加 `precheckState`。
- 汇总 `summarizePrecheck`（同在 todo.ts）：冲突 N · 未能试合 M · 未检查 K + 状态（已检查 / 部分完成 / 未完成 / 未检查）+ 首条原因。看板列头、总览、顶栏与 `heliu 待办 --precheck`（新增一行「试合：未完成 · 冲突 0 张 · 未能试合 36 张（原因…；这些卡不能当成无冲突）」，绑定行写「未能试合（原因）」）共用这一个函数。
- 看板：列头/总览「冲突 N · 未能试合 M」（M>0 黄色）；顶栏「冲突：部分完成 / 未完成（M 张未能试合：<首条原因>）」，全部有结果才写「已检查 HH:MM:SS」；卡片加「未能试合」标签，下一步改为「未能试合（原因）：重新试合或人工确认；落后 ↓N」，灯色仍按 M2 分组（落后/等你），不会是绿灯，也不写「无冲突」。
- 合并预演：新增档 `precheck_failed`「未能试合」，排在有冲突之后、未完成之前，建议动作「重新试合或人工确认」（`recheck`），**不进顺延**；合并单草稿 `tier` 同步、默认决定「待定」，正文多一节「未能试合」。等你回答的卡仍归未完成，原因里注明「另有分支未能试合」。
- `HELIU_DEBUG=1`：`runBoard` 从开始到监听逐步同步写 stderr（开始 / 加载项目 / 读台账 / 打包 / 监听 / 已监听 / 预热开始，带毫秒），供 M5 排查 launch.json 启动挂起。实测正常启动 33 ms 到「已监听」。
**验证**：新增 6 个用例（三态汇总四种状态、预演新档与等你回答、`HELIU_NO_SANDBOX=1` 子进程探针打 `/api/features`·`/api/release/preview`·`/api/overview`、同条件下 CLI 待办输出、HELIU_DEBUG 打点）。真实数据 `HELIU_NO_SANDBOX=1`：汇总 `failed 36 · conflicts 0 · status 未完成`，列头「冲突 0 · 未能试合 36」，预演 已进集成 22 · 未能试合 28 · 未完成 11（等你回答）· 顺延 11；正常环境仍是「已检查」、冲突 11、未能试合 0。前后三仓库 1174 项快照一致。

## 10. 收尾（Codex 第 2 轮建议的文案）
- 绿灯「可合并 · 试合无冲突」：下一步写「试合到 X 无冲突（试合无冲突 ≠ 已验收）」，同时落后时补「落后 ↓N，建议先同步基线」；图例加一句「绿灯 = 试合无冲突 ≠ 已验收；若落后基线，合并前请评估是否先同步」。
- 「需解冲突」「需同步基线」（含可合并但落后）的卡片展开态，每个未合并绑定加「复制给 Claude 会话」：复制「请在分支 <分支> 的 worktree（<目录>）里，把 <集成分支> 合并进来/同步基线并解决冲突文件：<文件列表>；两边功能都保留，解完 git add，不要 push。」（`web/prompt.ts`，只生成文本，看板不执行任何 git 操作）。
