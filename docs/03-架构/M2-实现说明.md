## 4. hooks
`hooks/hooks.json` 只注册 **SessionStart、Stop**：`{"command":"${CLAUDE_PLUGIN_ROOT}/bin/heliu-hook","args":[],"timeout":5}`。`args: []` 让它走 exec 形式（官方文档：有 args 即 exec、不经 shell）——本仓库路径含空格（`Mobile Documents`），shell 形式下不加引号的占位符会被拆开。
- SessionStart 输出样例（磁吸背夹真实 worktree）：
  `{"hookSpecificOutput":{"hookEventName":"SessionStart","additionalContext":"【合流】你在 文档仓/claude/bold-shaw-093e51，功能卡 F-0033『实现 EPP 网关 v0（代调 MCP / CLI）』（待合并）预约 vNext；落后主线 9 提交、落后集成分支 111。调用 heliu 工具时请传 cwd=\"…/bold-shaw-093e51\"。"}}`
  无卡时：「本分支暂无功能卡；若本会话在做新功能，请在明确需求后调用 heliu_feature_add 登记（标题用用户的一句话），否则忽略。」主线/集成分支上提示不建卡。项目外目录不输出。
- Stop：`session_id → 最后活动` 写缓存 sqlite（不写台账）；`待办` 用它参与「停滞」判断。
- 容错：空/坏输入、项目外、未知事件 → 无输出 exit 0；看门狗从进程启动算 270ms 未完成即 exit 0。
- **实测耗时**（含 sh 包装 + bun 启动，直接执行 bin/heliu-hook）：fixture 104 / 87 / 85 ms（直接 bun 跑 main.ts 82 / 81 / 81 ms）；磁吸背夹 iCloud worktree 122 / 95 / 100 ms（直接 bun 84 / 84 / 86 ms）。sh 包装开销约 4–16 ms（<30 ms）；看门狗预算改为 bun 启动后 260 ms。`tests/hook.test.ts` 断言三次均 <300ms，`tests/entry.test.ts` 断言包装开销中位数 <30ms。
- **WorktreeCreate 未注册（偏离任务卡）**：官方 hooks 文档写明配置 WorktreeCreate 会「替换默认的 git worktree 创建」，command hook 必须在 stdout 打印新 worktree 路径，"If the hook fails or produces no path, worktree creation fails"。只记录不建会让 `--worktree` / 子代理 worktree / 后台会话全部建不出来；代建又违反只读纪律。改为 SessionStart 时把「首次见到的 worktree」记进缓存（`worktree_seen` 表）；handler 里保留 WorktreeCreate 分支只做兜底。sync 草稿一律 `source: sync`。

## 9. 取舍与已知限制
- 预约到不存在的版本会自动新建（规划中）——验收步骤「预约 F-0001 v1.2 → 待办 v1.2」在新台账上要求这样；冻结/合并中/已发布的版本拒绝新预约。
- 任务卡以外的小增量：`feature rename`、`milestone rename`（vNext 改名时同步改卡）、`heliu_feature_set_status` 支持 `title`（Skill ③ 改名需要）。
- 「等你回答」取卡片写明的会话 + 对账里以「记录」关联到绑定分支的会话；会话正在运行（busy）时不算等你。
- ~~绑定分支已全部进主线的卡不计入待办~~ → 第 2 轮改为承诺层优先：只按台账状态计入，分支已进主线/集成分支时只给建议（见第 10 节）。
- 待办分组按任务卡优先级，「落后需同步」高于「停滞」，所以磁吸背夹 9 月的老分支落在「落后需同步」而非「停滞」。
- ~~bun 只在 `~/.zshrc` 的 PATH 里，桌面端启动的 Claude Code 可能找不到~~ → 已消除：入口包装依次找 `command -v bun` → `~/.bun/bin/bun` → `/opt/homebrew/bin/bun` → `/usr/local/bin/bun` → `$BUN_BIN`；都没有时 heliu 打印一行中文错误退出 1、hook 静默 exit 0。bun 装在其他位置时设 `BUN_BIN`（按要求排在最后，只作兜底，不能覆盖前面找到的 bun）。
- 根目录 `.mcp.json` 同时会被「在本仓库里打开 Claude Code」当成项目级 MCP 配置，此时 `${CLAUDE_PLUGIN_ROOT}` 不展开、heliu 连不上；以 plugin 形式加载时正常。
- 同一分支被绑到多张卡时 whereami 取编号最小的一张并提示其余卡号；sync 不会再为它建卡。
- status 摘要在磁吸背夹 100 列下 47 行（M1 收敛到 45；+2 行来自 ① 等你处理条目末尾时间戳导致的折行）。
- 文件锁是 mkdir 锁（3 s 等待、30 s 视为残留），只防同机并发登记撞号；台账在 iCloud 上（默认 `<主仓库>/.heliu/` 且主仓库在 iCloud）时多机同时写仍可能产生 iCloud 冲突副本。

## 10. 第 2 轮：Codex 第 1 轮反馈（零提交分支误判、承诺层优先）
现象：从 main 新建 worktree 分支、不提交就 `新点子`，`待办` 显示 0 条、把卡判成「已全部进主线」——零提交分支 tip 就在主线上，祖先判断恒真。修复（M1 对账层三档不改）：
1. **尚无独有提交**（`src/core/owncommits.ts`）：分支 tip 与主线/集成分支顶端同点 → 是；否则对已被包含的分支读 reflog（`git log -g`，只读），全部条目都是当前 tip = 自创建后从未移动 → 是；reflog 读不到时兜底「相对主线与集成分支都领先 0」。这类绑定进「开发中」组，文案「开发中 · 尚无提交」，不参与已合入/落后/冲突/停滞判断，主线上的提交时间也不算本功能的活动。
2. **承诺层优先**：想法/开发中/待合并 永远计入待办，只有 已合入/已进主线/已发布/已放弃 不计入（`countsTowardTodo`）。分支已被包含时只给「建议：是否标为已合入/已进主线？」，不自动改状态、不排除；`doneByGit` 字段保留兼容、恒为空。
3. `milestone list` 的待办数与 `待办` 用同一个函数（`todoFeatures`），`--json` 里多了 `counts`。
4. 「可合并」细分为「可合并 · 已进主线 / 已进集成分支 / 试合无冲突」；「无绑定」改名「尚未关联开发分支」；待办头部固定一行「下一版 = vNext（规划中）」。
5. `status --full`：与主线/集成分支顶端同点的功能分支写「进主线（无独有提交）」（分支视角三档不变）。
6. `sync` 同口径：尚无提交的 worktree 分支不再当「已进主线」跳过，照样建草稿（开发中、标「尚无提交」，标题无会话时取分支名而不是主线最后一条提交）。磁吸背夹 dry-run：**将新增 14 张**（文档仓 13、App 仓 1，多数是只做调研、没提交的会话，其中 4 个在等你回答）；本轮**未写入**真实台账。
测试 167 个全绿（新增：零提交卡计入「开发中」、已合入不计入、zeroCommit 集合优先、Codex 复现端到端、sync 零提交草稿、--full 标注）；演练前后三仓库 `.git` 快照一致。
