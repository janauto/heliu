# M10 任务卡：积木工作台——像本地客户端一样的看板

## 用户原话
「依照现代化产物风格来设计交互。像小白一样，通过合理的交互去拖拉拽，像 Arduino Block 那样。不会有密集如点云的各种复杂炫技的交互，只会有清晰易懂的一个个项目方块。像 WBS、Notion、项目管理甘特图那样形象地展示项目。优先优化视觉表达、交互与 UX，做到 GitHub 上 10K 量级。它将成为一个本地的客户端，像 GitHub Desktop 那样。」（2026-11-01）

## 一句话
把合流从「八个页签的对账单网页」改成「一个像 GitHub Desktop 的本地客户端」：左侧导航、中间是一块块看得懂的**方块**、右侧是方块详情；日常操作靠拖方块完成，像拼积木。后端接口与硬规则不变（只读被管理仓库、只写台账与合并单、合并在终端 yes 才执行）。

## 设计立场（为什么这样做）
1. **一个对象、一种画法**：无论在看板、时间线还是合流装配里，一条功能（有卡的功能卡 / 没卡的分支）永远是同一个「方块」。用户学会一种方块，就学会了全部页面。星图里「点 = 分支」的点云取消主视图资格（降为「更多 → 星图」保留，不删代码）。
2. **先说人话，再给事实**：方块第一行永远是「现在怎么样 / 该干什么」的人话（能拼上 / 要先对齐 / 撞了 / 等你拍板 / 还在做 / 还没登记），事实（落后 102、3 个文件冲突、试合目标）放第二行小字。事实与建议分开（CLAUDE.md 硬规则 6）。
3. **拖拽 = 唯一需要学的动作**：拖方块到版本列 = 预约；拖到合流轨道 = 排进合并单；拖到类型行 = 改类型。所有拖拽只写台账 / 合并单，和以前一样；每次松手都有 toast 说明写了什么，并给「撤销」。
4. **留白与层级**（用户反馈「太挤」）：8px 刻度；一屏只放一个主问题；列表默认只展开需要处理的组。
5. **本地客户端的壳**：标题栏 · 左侧栏 · 主区 · 右侧详情 · 底部状态栏，窗口缩放时逐级收起（侧栏 → 图标栏 → 底部标签栏），为二期桌面壳（Tauri / 桌面应用 mod pane）做准备；仍然是本机 127.0.0.1 网页，离线、无 CDN。

## 一、方块（Block）——统一的视觉语言
```
┌─●─●───────────────────────────────┐   ● = 两颗「积木钉」，颜色 = 状态
│ ● 功能  F-0041               ⋮⋮   │   类型字形 + 卡号；右侧拖柄
│ AI 电话助手来电路由与语气           │   标题（会话标题）
│ 等你拍板：要不要保留旧的按键路由？   │   人话一句（状态色淡底）
│ 文档仓 · vNext · 31 分钟前          │   仓库 · 预约 · 最后活动
│ ↓102 落后   3 个文件撞了            │   事实芯片（有才显示）
└───────────────────────────────────┘
```
- **状态 → 人话 → 颜色**（同 M2/M3 灯色，前端只读服务端 `light` / `group`，不自己再算）：

  | light | group | 人话 | 颜色 |
  |---|---|---|---|
  | green | mergeable | 能拼上 | 绿 |
  | yellow | behind | 要先对齐 | 黄 |
  | red | conflict | 撞了 | 红 |
  | purple | blocked | 等你拍板 | 紫 |
  | gray | active / stale / unbound | 还在做 / 没动静 N 天 / 还没绑分支 | 灰 |
  | （没卡的分支） | — | 还没登记 | 蓝 |
  | variant=merged-pending | — | 已合入 · 等你确认台账 | 绿虚线 |

- **密度三档**：`compact`（时间线左栏一行）、`card`（看板默认）、`detail`（右侧详情）。同一个组件 `<Block>`，props 控制。
- **物理感**：1px 边 + 2px 底边阴影（像摆在桌上的积木）；hover 抬 1px；拖起 scale 1.02、倾斜 1°、阴影加深；落位 160ms 回弹。`prefers-reduced-motion` 全关。
- **类型字形**（M8）：修复 ◆ 功能 ● 调研 ▲ 文档 ■ 工程 ⬢ 其他 ○。

## 二、应用骨架
- **标题栏 52px**：品牌标 + 「合流」；项目切换（按钮 + 下拉：项目名 · N 仓库 · 还欠 N；最后一项「接入新项目…」）；中间搜索框（筛选当前页方块；`/` 或 ⌘K 聚焦）；右侧「冲突检查」胶囊（未检查·点击检查 / 检查中 / 已检查 18:13·重新检查）、主题切换（跟随系统 / 浅 / 深）、刷新。
- **左侧栏 232px**：
  - 工作：**今天**、**看板**、**时间线**、**合流装配**
  - 了解：结构、会话（徽标 = 等你 N）、卫生（徽标 = 警告 N）
  - 底部：开始 / 接入、更多（星图）、教程、版本号
  - 宽度 < 1100px 收成 64px 图标栏（hover 出名字）；< 700px 变底部标签栏（四个工作页 + 更多）。
- **主区**：每页一个 page header（标题 · 一句话 · 右侧工具），内容区最大宽 1480px。
- **右侧详情 380px**（Inspector）：点任意方块滑入；Esc / 点空白关闭。内容：标题（可改名）、状态与人话、类型 / 模块（下拉即改）、预约（下拉即改）、每条绑定（仓库 · 分支 · 已进主线/集成/独立 · 落后主线/集成 · 试合结果与冲突文件列表 · worktree 路径）、会话（状态 · 等你的原文 · 复制会话 ID）、动作（复制「同步基线」指令 / 复制「解冲突」指令 / 看同步基线预演 / 排进合并单 / 一键改状态建议）。< 900px 变底部抽屉。
- **底部状态栏 28px**：数据时间 · 用时 · 「只读被管理仓库 · 合并在终端执行」。
- **Toast**：底部居中，带「撤销」（5 秒内可把预约改回去）。

## 三、四个主视图
### 1. 今天（替代「总览」）
- 顶部一块「下一版」大方块：`vNext · 规划中`，分段进度条（绿 能拼上 / 黄 要先对齐 / 红 撞了 / 紫 等你 / 灰 还在做，比例 = 张数），大号数字「还欠 N」，按钮「去装配 →」。
- 「现在最该做的」：`overview.actions` 的三句，每句一个带序号的方块，右侧按钮跳到对应页（含「集成分支」→ 合流装配、「会话」→ 会话页、「独立分支」→ 看板）。
- 「最近动的」：按 lastActivityAt 取前 6 张卡，横向一排 card 方块（可拖到上面的版本方块 = 预约）。
- 健康小行：集成分支 N 天未并回 / 本地无远端引用 N / 等你处理 N（沿用 overview.integrations 等字段，口径不变）。
- 「我有个新点子…」输入方块：回车 = `POST /api/features {title, milestone: next}`，toast「已登记 F-00xx，预约 vNext」。

### 2. 看板（替代「版本列」）
- 列 = `/api/features` 的 columns（里程碑按 milestones.yaml 顺序 + 未预约 + 已发布）；列头：名字 · 状态胶囊（下一版 / 规划中 / 冻结 / 合并中）· 「还欠 N」· 迷你分段条。
- 列内按 group 分组（等你拍板 → 撞了 → 能拼上 → 要先对齐 → 还在做 → 没动静），每组可折叠，默认展开前两组。
- 拖方块到别的列 = `PATCH /api/features/:id {milestone}`；不可放的列（已发布 / 冻结）变灰并写原因；松手 toast + 撤销。
- 列头「＋ 新点子」内联输入；列头菜单：复制合并 Prompt（复用 `/api/release/prompt`）。
- 顶部筛选芯片：全部 / 等你 / 撞了 / 能拼上 / 要先对齐；搜索框过滤标题 / 卡号 / 分支。
- 把 `board.tsx` 里的「同步基线预演」弹层、「复制给 Claude」指令、状态建议一键改状态迁到详情面板（inspector）。

### 3. 时间线（甘特 / WBS）
- 左栏 = WBS 树：仓库 → 模块 → 方块（compact），可折叠；右侧 = 时间轴。
- 条 = 方块的活跃区间：起点 = 功能卡 `created`（没卡的分支 = 第一条绑定会话的 createdAt，没有就只画点），终点 = lastActivityAt；颜色 = 状态；条上写标题；今天一条实线；里程碑 `target_date` 有值时画竖虚线 + 名字。
- 缩放：2 周 / 1 月 / 3 月；默认 1 月；横向滚动，今天默认靠右。
- 数据来源：`/api/features`（有卡）+ `/api/status`（没卡的分支，复用 `galaxy-model.ts` 里「没卡的分支」筛法与 `sessionEntry` 口径：会话入口不画为工作条，折叠成一行「会话入口 N」）。
- 把条拖到顶部的「版本芯片」= 预约；拖到左栏的模块名 = 改模块（`PATCH {module}`）。
- 纯布局函数放 `web/timeline-model.ts` 并写 `tests/timeline.test.ts`（区间计算 / 缩放刻度 / 分组计数）。

### 4. 合流装配（替代「合并预演」）
- 选版本（默认下一版）。左栏「这一版的方块」按 tier 分堆：能拼上（clean）· 已在集成分支（in_integration）· 撞了（conflict）· 没试出来（precheck_failed）· 还没做完（unfinished）· 拼不上（unmergeable）。
- 中间「合流轨道」：一条竖向轨道，从上到下 = 合并顺序（`ReleasePreview.items` 的 order，规则同 `heliu 合并 --预演`），每个槽位是一个方块 + 试合结果 + 决定三段开关（并入 / 待定 / 不并 / 顺延，沿用 `decision` 字面值）。拖方块进轨道 = `POST /api/release/decision {feature, milestone, decision:"并入"}`；改开关同一个接口。
- 右下常驻条：「生成合并单」（`POST /api/release/plan`）· 「复制合并 Prompt」（`POST /api/release/prompt`）· 一行粗体：**看板只排单，不执行合并：在终端运行 `heliu 合并 <版本>`，看完摘要输入 yes 才开始**。保留原文案「仅预演，不会执行合并（M4）」（测试断言）。
- 「刚合并完？同步一下」按钮 → 复用 `merge-flow.tsx` 的 `MergedPanel`。
- 预计顺延清单与合并单文件状态照旧显示（事实，不加断言）。

### 其余页（换壳、少改）
- 结构：保留 `structure.tsx` 逻辑，样式对齐新令牌；「现在该决定的」大数字改成 dchip 方块组。
- 会话 / 卫生 / 开始 / 星图 / 配对面板：只换壳（新令牌 + 新页头），功能不动。

## 四、拖拽实现约定
- 统一用 Pointer Events（鼠标、触屏都行），不用 HTML5 draggable：`web/dnd.ts` 提供 `startDrag({ payload, ghost, onDrop })`，用 `document.elementsFromPoint` 找带 `data-drop` 的目标，调用目标的 `canDrop(payload)` 决定描边颜色与提示文案。
- 可放目标文案格式：「放到这里：预约到 v1.2」「放到这里：排进合并单（并入）」；不可放：「已发布的版本不能再预约」。
- 松手后：先乐观更新（方块立即出现在新位置），请求失败回滚并 toast「没改成：原因」。

## 六、怎么算做成（验收口径）
1. 第一次打开落在「今天」，10 秒内看懂：下一版还欠多少、几块能拼上、几块等我；每个数字点进去都是方块列表。
2. 看板里拖一个方块到另一列，松手 1 秒内列头数字变化、toast 写明「写入台账」、5 秒内可撤销；拖到已发布列被拒绝并说明原因。
3. 时间线上能看出「哪些块最近在动、哪些块一个月没动」，里程碑日期线与今天线清楚；把一条拖到版本芯片能预约。
4. 合流装配里能按顺序看到这一版每一块能不能拼上；拖一块进轨道后合并单文件更新；页面任何地方都不执行 git 合并（代码中 `/api/release/*` 之外无新的写接口调用）。
5. 点任意方块，右侧详情里能改预约 / 类型 / 模块、复制同步 / 解冲突指令、看冲突文件列表。
6. 浅 / 深色、1440 / 1100 / 700 / 375 四档宽度都能用；`prefers-reduced-motion` 下无动画；`bun run typecheck` 与 `bun test` 全绿；离线无外链。
7. Codex 以普通用户视角走 1–5 条（≤3 轮）。
