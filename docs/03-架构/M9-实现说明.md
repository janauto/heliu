# M9 实现说明：会话入口 · 跨仓配对 · 三仓名实相符

任务卡见 [M9-任务卡.md](M9-任务卡.md)。这里记实现时的取舍、阈值和局限。

## 一、会话入口（空壳分支）

- **判定**：复用 `owncommits.isZeroCommit`（与待办里的「尚无提交」同一个函数，规则只有一套）。看板在 `BoardService.markEntries` 里对所有已被包含（已进主线 / 已进集成分支）的功能分支判一次，结果写进 `FeatureView.sessionEntry`，并随本次扫描缓存（`scan.zero`）。独立未合并的分支一律 `false`。
- **只在看板里填**：CLI 的对账结果不带这个字段（缺省）。`heliu 配对` 需要「分支有没有自己的提交」时，用 `pairing.ownCommitsOf` 现算（只算 worktree 里检出的那几条）。
- **边缘情况**：有提交但净改动为空（改了又撤、空提交）不算会话入口。判不了（git 超时）时按「有提交」处理，不会误把真实工作收起来。
- **真实数据对账**（2026-10-28）：文档仓 78 条分支里，会话入口 23 条，「有过提交、已合入」15 条（已进集成分支 13 条、已进主线 2 条），合计 38 条，正好是任务卡里「相对集成分支没有任何文件改动」的那 38 条。另有 40 条独立未合并，有真实改动。固件仓、App 仓各有 1 条会话入口。

### 各页口径

| 位置 | 会话入口怎么算 |
|---|---|
| 星图 | 不进类型行。每条泳道最下面单独一行「会话入口 N（M 已配对）」：空心小点，默认收起，不画汇入主流的线。**不随「显示已进主线」隐藏**，因为它的会话可能正在等你。时间按会话最后活动算。泳道头显示「有自己提交的 N + 会话入口 M / 总数」（Codex 第 2 轮建议：不写「工作 N」，免得被当成工作量排名）。不接「改类型」拖放 |
| 星图筛选 | 按件计：同一张卡绑了几颗星只算一件，没卡的分支一条算一件，没有可见分支的小卡星也算。「还没建卡」不含会话入口和已进主线的分支。「等你回答」含会话在等你的、没卡的分支（包括会话入口） |
| 星图（配对过的卡） | 同一张卡在别的仓库还有进行中的分支（没进主线，或是会话入口）时，这条已进主线的分支也画出来，同卡的星才看得见、连得上 |
| 结构页 | 会话入口不进「还没建卡」「落后需同步」。还没建卡、但会话在等你的入口，列进「等你回答」。页脚另列「另有 N 条会话入口分支（M 已配对）」。「星图里看」优先跳到有真实改动的那条绑定 |
| 待办 / 版本列 | 以卡为单位，口径不变；卡只绑了会话入口时，照旧显示「尚无提交」 |
| 卫生页 | 不变 |

真实数据下星图筛选与结构页一致：等你回答 16、有冲突 11、落后需同步 45、还没建卡 14（配对后是 13，因为新建 F-0062 收走了一条没卡的分支）。打开「显示已进主线」后也一样；Codex 第 1 轮指出过这里不一致，现在有测试守着。

## 二、跨仓配对

### 证据从哪来

桌面会话 JSON 的 `writtenBranches` / `gitAnchors` 只记会话自己所在的仓库：80 个文档仓会话里，一条固件仓、App 仓的记录都没有。所以证据只能从对话记录 `~/.claude/projects/<目录>/<cliSessionId>.jsonl` 里找。

- **只读本项目的会话**：对账结果里归属本项目的会话，按 `cliSessionId` 定位文件；根目录可用 `HELIU_TRANSCRIPTS_DIR` 注入。
- **匹配**：目标是「会话自己仓库以外」所有仓库的 worktree，包括仓库主目录。固件仓的 worktree 是仓库根的兄弟目录，所以必须用 `git worktree list` 的结果，不能只看仓库路径前缀。
  - 路径按「家目录之后那一段」匹配，`/Users/me/x`、`~/x`、`$HOME/x` 三种写法都认。Bash 命令里大多是 `~/` 写法。
  - 长的路径先匹配，后面不能紧跟路径字符，所以 `esp_claw` 不会误中 `esp_claw-aios`。
- **提取**：先用正则在整份文本里找路径，只有命中的那一行才 `JSON.parse`。
  - **写入**：`Edit` / `Write` / `NotebookEdit` / `MultiEdit` 的 `file_path` 落在该 worktree 下。
  - **提交**：`Bash` 命令提到该 worktree 且含 `git commit`。
  - **查看**：其余出现，都算查看。
- **缓存**：项目缓存 sqlite（`~/Library/Application Support/heliu/cache/<项目>.sqlite`，拒绝 iCloud）新增两张表。
  - `transcript_files` 记文件的 mtime、大小和目标集合签名，三者都没变就整份跳过。新建了 worktree，签名就变，会重新提取。
  - `transcript_evidence` 每行是「文件 × worktree」，记查看 / 写入 / 提交次数和最后出现时间。
- **性能**（真实数据 79 份、约 512 MB）：首次全量提取 0.8 秒；之后都没变时 0.0 秒。分析只在点「分析对话记录」或运行 `heliu 配对` 时做，**不在普通扫描或 hook 里做**。

### 分档阈值（`PAIR_THRESHOLDS`）

| 档 | 条件 | 默认 |
|---|---|---|
| 强 | 有写入或提交；该分支有自己的提交；占该会话跨仓出现总数 ≥ 10%；不是仓库主目录 | 勾选 |
| 中 | 有写入但不满足强档；或没有写入、但出现 ≥ 10 次且占比 ≥ 70% | 列出，不勾 |
| 弱 | 其余 | 折叠在「更多弱证据」 |

真实数据上又补了四条规则，都写成常量和测试：

1. **仓库主目录只算弱证据**：主目录常切换分支，现在检出的那条未必是当时那条。实测 `esp_claw` 主目录现在停在 `codex/media-hid-encryption`，十几个会话因为查看过主目录，被误判成中档。
2. **开在主线 / 集成分支上的会话不出建议**：主控会话、做集成的会话什么都碰，它的跨仓活动不是某个功能的另一半。
3. **共用分支降级**：同一条分支被 ≥ 3 个会话判为强档时，降为中档并注明「可能是发布 / 共用分支」。实测 `release/backclip-1.0` 被 5 个会话提交过。
4. **已绑在别的卡上**：只有中档以上才提示，并且不合卡。顺手碰一下的不打扰。

### 目标卡

- **会话 → 卡**：卡上记了这个会话，或者绑了会话所在的分支。
- **fork 出来的会话**：自己没有卡时，跟原会话的卡走（`spawnedFrom`），不另建重复的卡。
- **会话还没有卡**：确认时用会话标题建一张卡，同时绑会话所在的分支（它是入口，会话状态跟着卡走）和选中的分支，默认预约下一版。
- **这条分支已绑在别的卡上**：只提示「如果是同一件事请手动处理」，不能勾选。

### 事实说明（不是建议）

- **在别的仓库的主线 / 集成分支 worktree 里改动**：这条分支不能绑功能卡，只说明「记录显示曾在这个 worktree 里改动」，并注明这不代表改动现在一定还在这条分支里。实测「AI电话助手来电路由与语气定制」是在 `esp_claw-aios`（检出 `feat/aios-entry`，即固件集成分支）里改的，改文件 93 次、提交 9 次。
- **在分离 HEAD 的 worktree 里改动**：定位不到分支，只说明。

### 局限

- worktree 已删除的会话定位不到分支，不出建议。
- worktree → 分支按**现在**检出的分支，可能后来换过；界面上会写明。
- 实测「修复 dbd67483 蓝牙启动内存不足」的主要证据在 `esp_claw-a663`：它处在分离 HEAD 状态，而且只有查看、没有写入，所以不出建议也不出说明。这个会话是在旧提交上看代码。

### 真实数据结果（台账副本，2026-10-28）

- 有跨仓证据的会话：51 个（证据表里不同的 `cliSessionId`）。
- 规则收紧后的可操作建议：强 8、中 8、已绑在别的卡 5，事实说明 1 条，其余为弱证据。
- 任务卡里核实过的三个案例：
  - aios：落到事实说明，因为它直接在集成分支上改。
  - a663：分离 HEAD、只有查看，不出建议。
  - keymodel：两条分支早已分别绑在 F-0060、F-0044 上，只提示，不合卡。
- 浏览器里勾选默认的 8 条强档并绑定：7 张已有卡各加上固件仓 / App 仓分支，新建 1 张 F-0062「执行 AI 电话秘书 POC」。新卡同时绑了文档仓入口和 `feat/call-secretary`。真实台账未变。

- 依据里，改文件次数和提交次数为 0 时也照写，强弱一眼可比。
- 总览页「现在最该做的」：分析过、还有强档或中档建议没处理时，多出一行入口；没分析过就不提。

### 隐私（界面与 `heliu 配对` 都会显示）

1. 只读已归属本项目的会话的对话记录文件（`~/.claude/projects` 下），不读别的项目。
2. 缓存只存路径、次数、工具类别（改文件 / 提交）和时间，不存对话文字。
3. 删除缓存文件（`~/Library/Application Support/heliu/cache/<项目>.sqlite`）即删除全部提取结果，随时可重新分析。

## 三、改名

- `setRepoLabel` 只做文本级替换：在该仓库那一块里找 `label:` 那一行，只替换值，行尾注释保留。不整文件重写，避免丢掉手写注释。写完重新解析一遍，读回来的名字不对就恢复原文件并报错。找不到那一行，就提示用户手动编辑。
- **入口**：结构页页脚的「改名」按钮（`POST /api/project/label`），终端 `heliu project set-label <仓库> <名字>`。
- **何时提示**：项目有多个仓库、会话 ≥ 10 个、其中 ≥ 80% 开在同一个仓库，并且这个仓库有会话入口。真实数据是 78 个会话里 78 个都开在文档仓。名字里有「文档」时，建议改成「总仓（会话入口 + 文档）」。
- 不替用户改，提示里写明「只改 project.yaml 那一行」。

## 四、hook / Skill / 全局入口

- 【合流】提示（`whereamiContext`）在功能分支和无卡分支两种情形末尾，各加一句「去别的仓库开了分支 / worktree，就用 heliu_feature_bind（cwd 传那个 worktree）绑到同一张卡」。纯文案，没有新的 IO。
- `/heliu` Skill 新增「⑤ 跨仓库工作」，原「禁止事项」顺延为 ⑥。
- `examples/全局入口.md` 新增第 3 条。已装机器上的全局 CLAUDE.md 不会自动改：重跑 `scripts/install.sh`，只会更新带标记的那一段。
