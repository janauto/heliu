## 2. 数据流
- 入口 `App` 一次性 `useApi`：`/api/status`、`/api/overview?precheck=`、`/api/features?precheck=`、`/api/milestones`，30 秒自动刷新；各视图只从 `useApp()` 读，不再各自拉 features。
- 冲突检查（试合）沿用 M3：页面打开后自动 `GET /api/status?precheck=1` 一次；之后 `precheck` 为真时 overview / features 都带 `precheck=1`；标题栏胶囊显示 未检查 / 检查中 / 已检查 HH:MM:SS / 部分完成（failed > 0 如实写）。
- 写接口只有这些（与 M3–M9 相同）：`PATCH /api/features/:id`（milestone / type / module / status / title）、`POST /api/features`（新点子；带 `bind` 时从分支建卡）、`POST /api/release/decision`、`POST /api/release/plan`、`POST /api/release/prompt`、`GET/POST /api/merged`。没有新增写接口；没有任何地方执行 git 合并。
- 选中方块后数据刷新：`App` 用新 features 里同 id 的卡替换 `selected.card`，详情面板里的灯色 / 预约随之更新。

## 3. 方块（Block）
- `modelOfCard(card, { next })`：人话只从服务端字段推——`done` → 已合入 / 已进主线 / 已发布；`variant === "merged-pending"` → 已合入 · 等你确认台账；`light` purple → 等你拍板（事实 = needsAction 第一行）；gray 按 `group`：unbound 还没绑分支 / stale 没动静 N 天 / 其余 还在做；green 能拼上（事实 = note 或「试合无冲突」）；yellow 要先对齐（事实 = 落后哪条基线多少）；red 撞了（事实 = 要先解 N 个文件）。事实芯片：落后 N（取各绑定里最大的 behind，优先集成分支）、N 个文件撞了（各绑定 conflictFiles 之和）、没试出来（任一绑定 precheckState=failed）、没绑分支 / 分支不在本地、从 vX 顺延、验收档位。
- `modelOfBranch(f, repo, modules)`：没卡的分支固定蓝色「还没登记」，类型 / 模块用 `src/core/classify.ts` 的 `inferType / inferModule` 推测（与 M8 同一套词典）；`sessionEntry` 的分支加「会话入口 · 尚无提交」芯片。
- 三档密度：`card`（看板 / 今天 / 装配轨道）、`compact`（时间线左栏 / 装配左栏，一行）、`mini`（时间线条上）。两颗「积木钉」与左侧 3px 色条都是状态色；人话文字同样写出状态，不只靠颜色。

## 4. 拖拽（dnd.ts）
- Pointer Events，不用 HTML5 draggable：移动 ≥6px 才算拖（之前仍是点击）；拖起时克隆源元素做幽灵（`drag-ghost`，跟随指针、微倾 1.2°），`body.dragging`，每个已登记的落点回答 `canDrop(payload)`：`{ok:true}` 加 `drop-can`（虚线描边），`{ok:false}` 加 `drop-no`（变淡），`null` 不理会；悬停时加 `drop-hot`（不可放再加 `drop-bad`）并在指针旁显示文案（「放到这里：预约到 vNext」/「已发布的版本不能再预约」）。
- 松手落在可放目标上才调 `onDrop`；拖完吞掉紧随其后的 click（否则会顺手打开详情）；Esc 取消。请求与乐观更新 / 回滚由各视图的 `onDrop` 负责。
- 落点登记：`useDropTarget(spec)` 返回稳定的 ref 回调，spec 每次渲染可换（闭包拿最新 props）。

## 5. 骨架与响应式
- CSS Grid：`"title title" / "side main" / "status status"`，标题栏 52px、侧栏 232px、状态栏 28px；工作台 `.main` 自己滚动，背景是 22px 点阵（像 Blockly 的工作区）。
- < 1100px 侧栏收成 64px 图标栏（徽标保留）；< 700px 变底部标签栏（8 个图标，星图隐藏）、状态栏隐藏；右侧详情 < 900px 变底部抽屉。
- 主题：`:root` 浅色令牌；`@media (prefers-color-scheme: dark) :root:not([data-theme="light"])` 与 `:root[data-theme="dark"]` 深色令牌；标题栏「外观」菜单写 `localStorage heliu.theme`。
- 字体全部系统自带：中文苹方，数字 / 标题 `ui-rounded`（SF Pro Rounded），等宽 SF Mono；离线、无外链。
- `prefers-reduced-motion` 下全部动效关闭。

## 6. 四个主视图
（各视图实现细节见本节；接口与口径不变。）

### 今天（views/home.tsx）
- 「下一版」大方块：id 取 `app.next`（没到时退回 features / overview 带的），「还欠」= overview 下一版列的 `owed`；分段条按下一版列里未完成卡的 `group` 加总（能拼上 / 要先对齐 / 撞了 / 等你拍板 / 还在做），未试合时「撞了」写「未检查」而不是 0，另写「N 块没试出来（不算无冲突）」。它同时是落点：拖「最近动的」方块进来 = `PATCH {milestone: next}`，toast 带撤销（原值口径与详情面板一致）。
- 「我有个新点子…」= `POST /api/features {title, milestone:"next"}`；「现在最该做的」按句子关键词跳页（跨仓配对 → 结构 / 独立分支 → 看板 / 集成分支 → 装配 / 会话 → 会话页 / 卫生 → 卫生页）；「最近动的」= 未完成且有最后活动的卡按时间倒序前 6；「健康」沿用 overview 的集成分支 / 无远端引用 / 等你处理 / 卫生警告。

### 看板（views/kanban.tsx）
- 列来自 `features.columns`；列头：名字 + 状态胶囊（下一版 brand / 规划中 / 冻结 / 合并中；未预约、已发布用标题前的状态点）、「还欠 N」、`Bar thin`、能拼上 / 撞了 / 等你 小字（冲突未检查如实写）、「＋」在本列登记新点子（冻结 / 合并中 / 已发布列没有）、「⋯」菜单（复制合并 Prompt、在装配里打开、展开 / 收起全部分组）。
- 列内按 `GROUPS` 顺序分组折叠（状态存 localStorage `heliu.kb.open.<列>`），done 的卡最后一组。
- 拖放与乐观更新：本地只记一张「还没被服务端接管的移动」覆盖表，画面上的列 = 服务端数据 + 覆盖表，自动刷新不会冲掉进行中的移动；松手后卡先出现在目标列最前面再 `PATCH`，失败回滚；撤销 PATCH 回原列（原列已冻结 / 合并中时不给撤销并说明）。落位后展开所在组、滚到它并回弹。
- 深链：`#/kanban/F-0041` 展开、滚到并选中；`#/kanban/g:blocked` 切筛选芯片。

### 时间线（views/timeline.tsx + timeline-model.ts）
- `buildTimeline(report, features, { now, range, width })` 纯函数：时间窗（2 周 / 1 月 / 3 月，右侧留 2 天）、刻度（今天标签优先、不重叠）、行树（仓库 → 模块 → 条目，另有「还没绑分支」组与每仓一行「会话入口 N（M 等你）」）、里程碑日期线（只含 target_date）、`todayX`。
- 条的起止：`BoardCard` 上没有 `created`，所以有卡的条起点 = 各绑定 `lastCommitAt` 与绑定会话 `lastActivityAt` 里最早的（会话入口的提交时间不算，否则会被主线老提交拉长几个月），标 `approx` 画虚线边并提示「起点为近似（最早可见活动）」；终点 = `lastActivityAt`，没有就取绑定里最晚的，再没有画空心菱形；没卡的分支用主会话最后活动与最后提交的早 / 晚者。将来服务端补了 `created` 会自动改用、画实线。已完成的卡不画；已进主线且没卡的分支不画（同星图）。
- 拖放：条 / 左栏方块 → 顶部版本芯片 = `PATCH {milestone}`（没卡的分支 = `POST /api/features {bind}` 建卡并预约，不提供撤销）；→ 左栏模块名 = `PATCH {module}`（乐观更新、失败回滚）。左右两栏共用同一个 rows 数组保证行高对齐，悬停联动高亮。
- `tests/timeline.test.ts`：时间窗与刻度、`xOf` 单调、起止三种情况与截断、会话入口折叠计数、过滤规则、分组与行高、乐观更新只改一张卡、里程碑线。

### 合流装配（views/assembly.tsx）
- 数据 `GET /api/release/preview?milestone=`；左栏按 tier 分堆（clean / in_integration / conflict / precheck_failed / unfinished / unmergeable → 能拼上 / 已在集成分支 / 撞了 / 没试出来 / 还没做完 / 拼不上），每项 `Block compact`（找得到 BoardCard 用 `modelOfCard`，否则按 tierText 构造）；已在轨道的项变淡标「已在轨道」。
- 轨道：按 `order` 排决定为「并入」的项（in_integration 标「跳过：已在集成分支」、开关只禁用非当前项），每槽 序号 + `Block card` + 决定开关（并入 / 待定 / 不并 / 顺延；当前是「等它」时才多出第五项）+ 冲突文件展开 + reason（事实）与「建议：actionText」。合流点写每个仓库的集成分支（未配置如实写）。
- 拖进轨道 / 切开关都走 `POST /api/release/decision {feature, decision[, milestone]}`（卡写的是 next 且选的正是下一版时不带 milestone，避免服务端把 next 改成固定版本号）；乐观更新按卡号记最新一次请求序号，只有最新失败才回滚；成功 toast 取 message 第一句并带撤销。
- 底部常驻条：轨道上 N / 撞了 / 没试出来 / 预计顺延 + 「生成合并单」（`POST /api/release/plan`）+ 「复制合并 Prompt」（`POST /api/release/prompt` → `MergePromptPanel`）+ 粗体「看板只排单，不执行合并…」。顶部说明条保留原句「仅预演，不会执行合并（M4）。」（测试断言）。
- Codex 第 1 轮后：左栏每行方块下面一条小行「档位：… · 决定：…」，hover / Tab / 点选时「决定」原地换成开关（并入 / 待定 / 不并 / 顺延），所以改成待定后仍能继续改；拼不上的项「并入」禁用并写原因。方块颜色 / 人话一律来自 `modelOfCard`（与看板一致），档位只是另一个灰描边胶囊。看板「撞了」（按卡分组）与装配「撞了」（合并单档位、按卡 × 分支计，会话等你 / 还没做完的归「还没做完」）不等时，左栏标题下写明两个数字与原因。没绑分支的卡在合并单里是「拼不上（没有绑定分支）」默认顺延，左栏底部有说明与入口。
