## 2. 安装流程（`scripts/install.sh`）
| 步 | 做什么 | 说明 |
|---|---|---|
| 1 | 找 bun | `command -v bun` → `~/.bun/bin` → `/opt/homebrew/bin` → `/usr/local/bin` → `$BUN_BIN`；没有就打印安装命令退出（dry-run 继续用 `bun` 占位） |
| 2 | 依赖 | `node_modules` 不存在时先 `mkdir node_modules.nosync` + `ln -s node_modules.nosync node_modules`（iCloud 不同步），再 `bun install --cwd <仓库>` |
| 3 | 找 claude CLI | 桌面内置 `~/Library/Application Support/Claude/claude-code/*/*/claude.app/Contents/MacOS/claude` 按版本 `sort -V` 取最高（本机 2.1.308），否则 PATH 里的 `claude`；都没有就跳过 4、5 |
| 4 | user 级 MCP | `claude mcp add -s user heliu -- "<仓库>/bin/heliu" mcp`（`bin/heliu` 是 sh 包装，自己找 bun；`--no-mcp` 跳过） |
| 5 | marketplace + 插件 | `claude plugin marketplace add "<仓库>"` → `claude plugin install heliu@heliu-local`（`--no-plugin` 跳过） |
| 末 | 打印验证命令 | `claude mcp list` / `claude plugin list` / `bin/heliu doctor`，以及看板、接入新项目的命令 |
- 每条命令先打印（带引号的路径原样显示中文，可直接复制）再执行；某条失败（例如已经装过）只警告、继续下一步。
- `uninstall.sh` 反向：`plugin uninstall heliu@heliu-local` → `plugin marketplace remove heliu-local` → `mcp remove -s user heliu`；不删注册表、台账、缓存与 node_modules，结尾列出它们的位置。
- 本机 `--dry-run` 实测输出见 `tests/onboard.test.ts`（断言 bun install、mcp add、marketplace add、plugin install 四条命令都在、退出码 0）。

## 3. marketplace 结构（偏离任务卡，原因在下）
```
<仓库根>/.claude-plugin/plugin.json        插件清单（name heliu，M2 已有）
<仓库根>/.claude-plugin/marketplace.json   {"name":"heliu-local","owner":{…},"plugins":[{"name":"heliu","source":"./",…}]}
<仓库根>/.mcp.json · hooks/hooks.json · skills/heliu/SKILL.md · bin/heliu · bin/heliu-hook
```
任务卡与派单写的是 `marketplace/.claude-plugin/marketplace.json`、source 指回仓库根。官方 marketplace 参考写明：相对路径 source 必须以 `./` 开头、**含 `..` 直接校验失败**，且相对路径从 marketplace 根解析——放在 `marketplace/` 子目录里没法合法地指回上一级（软链会被校验报「traverses a symlink」，`url`/`command` 源要写死本机绝对路径或会把仓库拷进缓存、丢掉 node_modules）。所以把仓库根本身当 marketplace 根：`source: "./"`，用目录源 `claude plugin marketplace add <仓库根>` 添加后**原地加载**，改代码不用重装。
校验（桌面内置 CLI 2.1.308）：`claude plugin validate <仓库根>/.claude-plugin/marketplace.json` → ✔ Validation passed；`claude plugin validate <仓库根>` → 通过，警告两条（根 CLAUDE.md 不作插件上下文；缺 icon），与 M2 相同。

## 4. 接入向导（`heliu project add <路径>`）
猜测规则（全部只读 git：`rev-parse`、`remote`、`symbolic-ref`、`show-ref`、`for-each-ref [--merged]`、`worktree list`）：
- 远端：`--remote` > `origin` > 第一个远端。主线：`--main` > `symbolic-ref refs/remotes/<远端>/HEAD` > 本地有 main / master > 当前检出分支。
- 集成分支候选（都要求未进主线、领先主线 >0）：① 名字含 merge / integration / release，按领先主线数排序；② 名字不像但包含 ≥2 条未进主线的其他分支（像集成分支在用），按包含数排序。只是「叠在另一个候选之上」的分支（包含它、却只多包含它本身，典型是从集成分支切出的功能分支）排后面；包含数相同时主目录正检出的优先。默认取 ① 的第一个，没有 ① 取 ② 的第一个，都没有就不设。`--integration` 指定时直接用。
- iCloud：路径含 `Mobile Documents`。
流程：打印中文摘要（主线/远端/集成分支及原因、候选列表、iCloud、规模、台账位置、注册表位置、「以上全部来自 git 只读命令」）→
- 交互终端：有候选时问「集成分支选哪个（序号，0 = 不设）」，再问「确认写入注册表并建台账？[Y/n]」，回 n 什么都不写；
- `--yes`：不问，按猜测/参数写注册表并 `init` 台账；
- 没有终端也没加 `--yes`（脚本、旧测试）：保持 M1 行为，只登记注册表、不建台账，并提示怎么补。
台账位置：项目已设 `ledger` 就沿用；`--ledger repo` = `<仓库>/.heliu/`（会在仓库里多一个未跟踪目录，摘要里写明）；`--ledger <目录>` 自定义；**缺省放 heliu 数据目录** `~/Library/Application Support/heliu/projects/<项目>/ledger`（与磁吸背夹一致，不往被管理仓库写任何文件）。
集成分支猜测对照：磁吸背夹文档仓 → `claude/merge-features-refactor-143693`（名字像，领先 102，包含 13 条）✔；固件仓 → 名字规则会先选 `release/backclip-1.1`（实际是产品主线，集成分支是 `feat/aios-entry`，在候选 ② 里包含 27 条），说明「名字像」优先有误判，交互时请看候选再选。

## 7. 已知限制
- 安装脚本未在本机真装（按派单只跑 `--dry-run`）；`claude mcp add` / `plugin install` 的真实输出与「已装过」时的返回码由 Fable 真装时确认。
- user 级 MCP 与插件自带的 MCP 同名并存时，会话里 heliu 工具会出现两份（`mcp__heliu__*` 与插件那份）；`--no-mcp` 可只留插件那份。是否默认去掉 user 级注册，留给真装后决定。
- 安装脚本不把 `heliu` 放进 PATH（README 给了 `ln -s` 写法），避免改系统目录。
- 向导的「名字像」规则会把 `release/*` 产品线当成集成分支候选第一名（固件仓即如此）；交互模式会列候选让你选，`--yes` 时请配合 `--integration`/`--main`。
- 注册表有了第二个项目（patent-figure-kit）后，在任何项目目录之外不带 `--project` 运行命令会提示「请用 --project 指定」（以前只有一个项目时会默认用它）。
- 交互提问用 Bun 的 `prompt()`，只在 TTY 下出现。

## 8. 终验反馈：看板预演与合并单统一规则
- 现象：看板「合并预演」把 App 仓 F-0060、F-0061 判「无冲突 → 合入」，`heliu 合并 vNext --预演` 判「无法合并 → 顺延（仓库未配置集成分支）」——两套规则。
- 改法：M4 `previewRelease` 拆出纯计算的 `buildReleasePlan`（只读仓库、不写文件，可传入已有的试合扫描），`previewRelease` = 它 + 写盘。看板 `GET /api/release/preview` 直接调用它（传看板缓存的试合扫描），只把合并单 items 的 状态 / 档位（`TIER_OF`）/ 建议动作（`ACTION_TEXT`）/ 决定 / detail 映射成表格字段，自己不再判档；`POST /api/release/plan` 改为调用 `previewRelease`，写 schema 2 合并单——与 CLI 同一个文件、同一格式，`heliu release set` 改过的决定看板上也看得到（「已改」）。M4 读到旧版看板草稿时先备份的兼容分支保留，看板不再产生这种草稿。
- 档位多一档「无法合并」（`unmergeable`，分支不存在 / 仓库未配置集成分支等，默认顺延）；表格加「决定」列；仓库没配集成分支时预演页顶部提示「<仓库>未配置集成分支：heliu project add <路径> --integration <分支>，或编辑 project.yaml 的 integration」。
- 磁吸背夹实测（只读，未写合并单）：看板预演 61 项与 `buildReleasePlan` 逐项（卡号、分支、档位、动作、决定）完全一致；F-0060、F-0061 =「无法合并 · 顺延 · 仓库未配置集成分支」，顶部出现 App 仓提示；三仓库快照零变化。
- 测试：`tests/board.test.ts` 改为 M4 口径（会话在跑 → 未完成；卡片「开发中」→ 未完成，fixture 里需要按 git 判的卡改为「待合并」），新增「与 buildReleasePlan 逐项一致」「未配置集成分支 → 无法合并 + 提示」「写合并单后 release set 改的决定看板可见、刷新保留」。
