# M4 任务卡：按里程碑合并（合并单 → 预检 → 执行 → 顺延）

## 目标
把用户手写的《总分支合并与重构方案》勾选表变成可执行的合并单：一句"合并 v1.2"→ 预演 → 确认 → 按顺序合入集成分支 → 冲突交子代理 → 打 tag → 发布说明 → 未完成项显式顺延。**这是全项目唯一会写被管理仓库的阶段**，必须有确认、有回滚记录、不碰用户的工作目录。

## 命令
- `heliu release preview <里程碑>`（只读）：预约到该版的功能 → 每个绑定分支的三档状态、`merge-tree` 试合冲突、落后数、会话状态 → 生成合并单草稿 `<ledger>/releases/<里程碑>.md`（frontmatter 机器段 + 人读勾选表）。顺序：已进集成（跳过）→ 无冲突 → 有冲突 → 未完成（开发中/等你回答，默认"顺延"，可改"等它"）。
- `heliu release run <里程碑> [--dry-run] [--yes] [--to-main]`：按合并单执行。无 `--yes` 时逐条确认。
- `heliu release rehearse <里程碑>`：把主仓库 `git clone --shared` 到 `~/.cache/heliu/rehearsal/<项目>/<时间>/`，在克隆上完整跑一遍 run，输出结果与耗时。**验收只在 rehearse 上做，真仓库由用户手动触发。**
- `heliu release rollback <里程碑>`：按合并单记录的 `old_sha` 用 `update-ref` 把集成分支指回去（只回退 heliu 自己移动过的引用）。
- 中文别名：`heliu 合并 v1.2 --预演`、`heliu 合并 v1.2`、`heliu 演练 v1.2`。

## 合并机制（不碰 iCloud 工作目录）
1. **无冲突分支**：纯对象库合并——`merge-tree --write-tree` → `commit-tree <tree> -p <集成> -p <分支>` → `update-ref refs/heads/<集成> <new> <old>`（带旧值校验）。不需要工作树。
2. **有冲突分支**：在 `~/.cache/heliu/worktrees/<项目>/<里程碑>/`（**非 iCloud**）`git worktree add --detach` 集成分支 → `git merge --no-commit <分支>` →
   - 对 project.yaml `union_files`（磁吸背夹：`README.md`、`嵌入式/README.md`、`业务/AI-Coding业务与进度.md`）用 `git merge-file --union`，再按"新日期在前"排序段落（可配置关闭）；
   - 其余冲突交**解冲突子代理**：`claude -p --model opus --permission-mode acceptEdits --allowedTools "Read" "Edit" "Bash(git diff *)" "Bash(git add *)" "Bash(git status *)" --max-budget-usd 2 "…"`，提示词包含两侧分支的功能卡标题与首条提交说明，要求只解冲突、不重构、解完 `git add`；
   - 若 project.yaml 有 `checks`（如 `bun test` / 固件 `host_tests.sh`），合并后在该 worktree 里跑，失败则停下来问；
   - `commit` → `update-ref` 回到集成分支 → `worktree remove`。
3. **完成**：`tag -a <里程碑> -m "<发布说明摘要>"`；`--to-main` 时若能快进则 `update-ref main`，否则列出来问。**绝不 push**，结尾提醒"N 个引用未推送"。
4. **顺延**：未合入的功能 → `milestone: next`、`rolled_from += [<里程碑>]`；里程碑状态 → `已发布`；发布说明 `releases/<里程碑>.md` 追加"已合入 / 顺延 / 冲突处理 / 旧引用（可回滚）"。

## 安全闸
- 合并前校验：集成分支 `old_sha` 与合并单一致，否则中止（说明仓库在预演后动过）。
- 每次 `update-ref` 记录 `{ref, old, new, time}` 到合并单，供 rollback。
- 只写 `refs/heads/<集成>`、`refs/tags/<里程碑>`、（可选）`refs/heads/<主线>`；不动任何功能分支，不删任何东西。
- 临时 worktree 一律在 `~/.cache/heliu/`，执行完即删；意外中断时下次启动提示清理。

## 验收（Fable）
1. fixture：3 条无冲突 + 1 条冲突（union 文件）+ 1 条冲突（普通文件，用 stub 解冲突器）+ 1 条未完成 → preview 顺序正确；run 后集成分支包含 5 条、未完成项顺延且 `rolled_from` 正确；rollback 后引用回到 old。
2. `heliu release rehearse v1.2 --project 磁吸背夹`：在克隆上对真实合并单执行，报告每条结果、索引文件冲突走 union、普通冲突由 Opus 解决（记录轮次与花费）、tag 存在、未推送提醒。
3. 真仓库零写入（rehearse 期间对三个真实仓库做快照比对）。
