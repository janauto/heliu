# M3 任务卡：中文看板（本机 Web）

## 目标
把 M1 对账 + M2 台账合成一张"10 秒看懂"的页面：v1.2 还欠什么、哪些能合、哪些在等我、仓库健康如何。只读为主，少量动作（预约改期、改名、同步基线预演）通过 API 回写台账；**不在看板里执行合并**（M4）。

## 形态
- `heliu board [--port 7788] [--open]`：Bun + Hono 本机服务，`/api/*` 返回 M1/M2 的 JSON（复用 `ReconcileReport`、台账结构），前端单页（Preact + htm 或 Bun 打包的 TSX，产物进 `dist/`，不依赖 CDN，离线可用）。
- 中文、浅/深色随系统、手机宽度可看（远程控制时在手机上看）。
- 自动刷新：每 30s 拉 `/api/status`（M1 扫描 <1s）；手动刷新按钮。

## 页面
1. **顶部健康条**（每仓库一行）：主线 vs 远端 ↑↓；集成分支领先主线 N、M 天未并回（≥3 天标红）；从未推送 N；worktree 脏/未知；卫生警告数（点击跳卫生页）。
2. **版本列**（主视图）：列 = 里程碑（`待办 v1.2` | `规划 v1.3` | `未预约` | `已发布`），列头"还欠 N 项 · 可合 a · 冲突 b · 等你 c"。卡片 = 功能：
   - 标题（会话标题/标签）、仓库徽标、分支（随机名显示标签，hover 看原名）
   - 五色灯：绿=可合（已进集成或 merge-tree 无冲突且不落后）、黄=落后需同步、红=试合冲突（列出冲突文件数）、紫=等你回答（显示 needs_action 原文）、灰=停滞 ≥7 天 / 无绑定
   - 行内数字：主线↑/↓、集成↑/↓、最后活动
   - 动作菜单：改预约版本、改名、标记放弃、复制"打开会话"链接（`claude://` link 来自会话 JSON）、「同步基线（预演）」= 显示 `merge-tree` 把主线/集成合入本分支的冲突文件列表（只预演，不执行）
   - 拖拽卡片到另一列 = 改预约（PATCH `/api/features/:id`）
3. **卫生页**：M1 hygiene 的四类警告与提示，每条附"建议命令"（只显示，不执行）。
4. **会话页**：M1 sessions 表，按"等你 / 运行中 / 已完成 / 已归档"分组。
5. **合并预演页（只读）**：选里程碑 → 列出预约功能按建议顺序（先已进集成、再无冲突、再有冲突）、每条试合结果、预计顺延项；"生成合并单"按钮写 `releases/vX.md` 草稿（M4 执行它）。

## API
`GET /api/status`、`GET /api/sessions`、`GET /api/hygiene`、`GET /api/milestones`、`GET /api/features?milestone=`、`POST /api/features`、`PATCH /api/features/:id`（milestone/title/status）、`POST /api/sync`、`GET /api/release/preview?milestone=`、`POST /api/release/plan`（写草稿）。所有写操作只动台账，绝不动被管理仓库。

## 验收（Fable）
1. `heliu board --project 磁吸背夹` 打开后 2 秒内渲染；用桌面应用内置浏览器截图确认中文、对齐、深色模式。
2. 看板顶部能一眼读出：集成分支 N 天未并回、从未推送数、等你处理数。
3. 拖一张卡到另一版本列，刷新后仍在（台账已写）。
4. 合并预演页对 v1.2 给出顺序与冲突文件（与 `--precheck` 一致）。
5. 手机宽度（375px）可读。
6. 全程三仓库零写入。
