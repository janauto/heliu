## 闸门二（Codex）
### 第 1 轮（2026-10-26 04:20，冻结快照 e354506）
- **verdict：不通过**。认可：无需填表即可登记/预约/改期；MCP 冒烟通过、工具描述中文；hook 80–90ms；真实项目 dry-run 不重复建卡；三仓库 + 台账 6761 项快照无变化。
- 阻塞（1 条，真实逻辑漏洞）：刚从 main 开出的功能分支（零独有提交）被 git 祖先判断当成"已进主线"，功能卡从待办消失，待办显示"未合入 0 条"，而 `milestone list` 显示 1/1 不一致。首次提交后才出现。
- 建议：可合并细分（已进集成 / 试合无冲突）；"无绑定"改"尚未关联开发分支"；卡片同时保留落后数/停滞天数/待回答；固定显示"下一版 = 哪个"；补一次桌面真实会话验收。
- 处理：修复规则——只有 ≥1 独有提交且被包含才算已合入；台账 status 为想法/开发中/待合并的卡永远计入待办，git 只负责分组与灯色；list 与 todo 共用同一计数函数。→ Opus 第 2 轮。

### 修复（Opus，提交 9e4e9d8）
- "尚无提交"判定：分支 tip 与主线/集成 tip 同一提交 → 尚无提交；被包含但不同点时读该分支 reflog（只读 `log -g`）判断是否从创建起没动过。已合进主线的旧分支因此不会被误标。
- 台账 status 为想法/开发中/待合并的卡永远计入待办；已被包含时只提示"是否标为已合入"，不自动改。
- `milestone list` 与 `待办` 共用计数函数；可合并细分为"已进集成分支 / 试合无冲突"；"无绑定"改"尚未关联开发分支"；头部固定"下一版 = …"；`--full` 同点分支标"（无独有提交）"。
- `sync` 同口径：零提交 worktree 分支也建草稿并标"尚无提交"（磁吸背夹 dry-run 会多 14 张，4 个等你回答）。Fable 接受：在途意图应可见。
- 测试 167 个全绿；三仓库 `.git` 快照一致。端到端复现 Codex 的步骤已固化为测试。

### 修复（Opus，提交 af91deb）
- 判定顺序：有 `sourceBranch`（git-worktrees.json / 会话 JSON）→ `rev-list --count 来源..分支`，>0 有独有提交，==0 再看 reflog 是否有过提交；无来源 → 读 reflog（commit/cherry-pick/revert/merge 算有过提交；仅 Created from/快进/reset 算尚无提交）；reflog 不可读 → 兜底规则。reflog 判断置于"tip == 主线 tip"之前（避免被主线快进合并的分支误判）。Fable 接受。
