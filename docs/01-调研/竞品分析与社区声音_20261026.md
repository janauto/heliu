# 竞品分析与社区声音（2026-10-26，约 30 次检索；Star 数为抓取当日页面值）

## 结论先行
**没有现成工具能直接满足 80% 的需求。** 最接近的组合是「Claude Code 桌面版（执行）+ Backlog.md（规划）」，约覆盖 60%。**"功能预约进版本、发布时清点在途功能、分支落后检测、按里程碑合并、顺延可见"这一层，目前没人做。**
（Reddit 拒绝抓取，社区声音取自 HN、V2EX、Substack、Dev.to、LINUX DO。）

### 3. git 层
- **Graphite**：堆叠 PR，2025-12 被 Cursor 收购 [TechCrunch](https://techcrunch.com/2025/12/19/cursor-continues-acquisition-spree-with-graphite-deal)。
- **jj**：workspace 可多 agent 共用仓库，但官方把 git worktree 列为不支持 [文](https://wavect.io/zh/blog/git-worktrees-vs-jujutsu-ai-coding-agents/)。
- **git-town**：`git sync` 按分支谱系依次更新 [docs](https://www.git-town.com/stacked-changes) → 可作"落后分支同步"参考。
- **GitHub merge queue / Mergify**：PR 级、团队向，Mergify 2026-08 支持堆叠 PR 顺序合入 [changelog](https://docs.mergify.com/changelog/2026-08-12-merge-github-stacked-pull-requests-with-the-merge-queue/)。不是按里程碑合并。
- **Entire Checkpoints**：把 agent 会话挂在每个 commit 上，存 `entire/checkpoints/v1` 分支 [报道](https://rcpmag.com/articles/2026/02/12/ex-github-ceo-thomas-dohmke-unveils-entire.aspx)。
- **git-ai**：Git Notes 记录每行 AI 作者，Thoughtworks 雷达"评估" [radar](https://www.thoughtworks.com/radar/tools/git-ai)。

### 4. 官方能力
- **Claude Code 桌面版** [docs](https://code.claude.com/docs/en/desktop)：worktree 开关、`.worktreeinclude`、Create PR、Auto-fix、Merge when ready、PR 合并后自动归档、会话分组、跨会话列出/读取/发消息、云会话。**无看板或里程碑视图。** 本机还见到 `sync_with_base_branch`、`set_auto_merge`、侧栏分组等工具（无公开文档）。
- **Agent teams**：仅 CLI 实验功能，共享任务列表与依赖，不能跨会话 [docs](https://code.claude.com/docs/en/agent-teams)。
- **OpenAI Codex app**：2026-02-02 发布，自带 worktree 与审查队列 [公告](https://openai.com/index/introducing-the-codex-app/)。

**Top 5 痛点**：① 合并集成痛，含"文本无冲突、语义冲突"；② 审查量随并行数膨胀；③ 失去全局视图——不知道哪个会话做哪件事、做没做完（正是用户的"合并一版漏功能"）；④ 环境抢资源（端口/数据库/磁盘）；⑤ 合并顺序与分支落后全靠手工。
**Top 5 想要的功能**：① 会话-任务-分支一一对应的统一看板；② 自动 rebase/同步落后分支；③ 合并队列带门禁与顺序；④ 每 worktree 独立环境；⑤ 冲突在写代码前预警（Foremerge：agent 先声明计划改哪里）。

## 三、复用结论
**C1 能直接用的？没有。** 最接近组合「Claude 桌面版 + Backlog.md」≈60%；单个最像的是 Vibe Kanban，但无里程碑且公司已关停。
**C2 可站在肩膀上**：Backlog.md（MIT，TS/Bun，任务即 Markdown，`version` 字段成本低）；Vibe Kanban（Apache-2.0，参考"卡片驱动 worktree"逻辑，停更风险）；Paseo / Emdash（Apache-2.0，执行层备选，但用户已绑定 Claude 桌面版）。不宜作底座：Conductor（闭源）、Claude Squad/Mux（AGPL）、Superset（Elastic 2.0）、Taskmaster（Commons Clause）、Beads（Go 栈，可作外部依赖）。
**C3 没人做的（差异化）**：① 功能预约进版本；② 发布时清点在途功能（等它 / 顺延，不悄悄漏）；③ 分支落后检测 + 一键同步并与里程碑绑定；④ 按里程碑一键合并（集成分支、依赖顺序、测试）；⑤ 新功能自动从最新集成分支开 worktree；⑥ 大版本待办 + 中文小白可视化 + CLI/MCP/Skill 三调用面。
**建议路线**：别从零造。数据层沿用 Backlog.md 的"任务即 Markdown"思路并加版本字段，执行层直接用 Claude 桌面版的会话与 worktree，合并层写 git 脚本；自己只写薄薄一层"版本列车"胶水，对外提供 CLI、MCP、Skill。
