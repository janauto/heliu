## 对工具选型的启示
1. **不造会话启动器**：桌面 app 的 worktree 会话是执行单元，工具只做"索引 + 编排"层；主键用"cwd 真实路径 + 分支"。
2. **形态**：一个核心引擎 + 本地 CLI + stdio MCP server + 可选本机网页看板；不做桌面 app。
3. **主控会话内可用 app 自带工具**（list_sessions、start_session、侧栏分组、sync_with_base_branch、PR 绑定）→ 做成 Skill。
4. **数据落点**：里程碑定义与验收记录用 Markdown/YAML 进各仓库；运行时索引放 `~/Library/Application Support/<工具>` 或 `~/.cache`，**不放 iCloud**；Obsidian 只做单向导出，用受控名，不写 `- [ ]`。
5. **一个里程碑跨多仓库**：项目 → 多仓库 → 多分支/worktree。
6. **合并沿用验证过的做法**：集成分支、合并顺序、禁改/公共文件清单、冲突热点追加式取并集、分层证据（源码/模拟/构建/安装/实机）。patent-figure-kit 的 impl-contract + acceptance 可做模板。
7. **ChatGPT 二次验收可选开关**，底层 `codex exec review --base` / `--output-schema`，记录轮次（≤3）。
8. **看板必须显示 git 卫生**：未推送、长期未合并、worktree 脏、远端不叫 origin。
9. **零侵入采集**：在 Stop/SessionEnd/UserPromptSubmit 钩子链追加记录；注意链上已有 paseo、rmrj、codex 插件，控制超时。
10. **桌面 app 数据结构内部无文档**，解析器容错、只读。
