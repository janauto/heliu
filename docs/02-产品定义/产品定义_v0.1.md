# 产品定义 v0.1 —— 合流（Heliu）

> 工作名「合流」：灵感像支流，版本是合流处。CLI / MCP 名 `heliu`。名字可改，不影响结构。
> 状态：初稿，待竞品复用结论后定稿技术底座；本文件只定"做什么、不做什么、怎么算做成"。

## 1. 一句话
给一个人、同时开十几个 AI 会话、跨多个仓库开发的开发者，一张**随时可信的对账单**：每个点子在哪条分支、预约进哪一版、离主线落后多少、合并会不会撞；合并一版时不漏、不乱、不冲突，漏掉的自动顺延并显式提醒。

## 2. 用户与场景（来自现场证据）
- 一个人，Claude 桌面应用 Code tab，新建会话默认开 worktree；同一项目 19 个活跃会话、75 个分支、54 个 worktree。
- 一个"项目"跨三个仓库（iCloud 文档仓、固件仓、App 仓），版本整合发生在旁路集成分支上，4 天没并回 main。
- 合并本身已经要单开会话处理（4/19 个会话在做合并/同步/解冲突）。
- 文档仓在 iCloud 上，`git status` 会卡死；任何扫描必须只读对象库、带超时。
- 有既定规矩：未经要求不 push、不建 PR、不 amend；验收分"已合并 / 已构建 / 宿主测试 / 实机通过"。

## 3. 用户会怎么说（口语化入口 → 动作）
| 用户的话 | 工具做什么 |
|---|---|
| "我有个新点子：让背夹支持 X，先并行做着" | 建功能卡 → 自动绑定当前会话/分支 → 默认预约到"下一版" |
| "这个预约到 1.2" / "这个不急，放 2.0" | 改预约版本，记录变更 |
| "1.2 还欠什么？" | 列出预约到 1.2 但未合入的功能，按状态分组（开发中 / 待合并 / 阻塞等你回答 / 没动静 N 天） |
| "现在能合吗？" / "合 1.2 会撞什么？" | 对每条分支 `merge-tree` 试合，报冲突文件、基线落后数、未提交改动、未推送 |
| "合并 1.2" | 生成合并单（顺序、预检结果、顺延项）→ 用户确认 → 逐条合入集成分支 → 冲突交给解冲突子代理或停下来问 → 打 tag → 写发布说明 → 未完成项顺延到 1.3 并置顶 |
| "我要用 X 功能，它带了最新的东西吗？" | 报 X 所在分支落后主线/集成分支多少，提供"同步基线"动作 |
| "哪些分支该清了？" | 已合并但目录还在、目录名≠分支名、孤儿条目、残留 lock → 只建议，不自动删 |
| "给我看看板" | 打开本机网页看板（或桌面应用内 pane） |

## 4. 实体模型与状态机
### 功能（Feature）
`想法 → 开发中 → 待合并 → 已合入(集成分支) → 已进主线 → 已发布`
- 侧向状态：`阻塞-等你回答`（来自会话 postTurnSummary.needs_action）、`停滞 N 天`、`已放弃`。
- 验收档位（独立字段，合并不自动提升）：`已合并 / 已构建 / 宿主测试 / 实机通过`。
- 绑定：0..n 个 {仓库, 分支, worktree 路径, 会话 ID, PR}。一个功能可跨多仓库多分支（如固件 + App）。
- 名字来源：桌面应用会话标题（中文、现成），用户可改。

### 版本（Milestone）
`规划中 → 冻结(不再接新预约) → 合并中 → 已发布`
- 字段：名字（v1.2）、目标日期（可空）、集成分支名、目标主线分支、发布说明路径。
- 派生视图：**待办** = 预约到本版且未"已合入"的功能。

### 预约（Reservation）
功能 → 版本，多对一。合并时未兑现 → **自动顺延到下一版并打标"从 v1.2 顺延"**，出现在新版待办顶部。顺延永远显式，永不静默丢弃。

### 对账（Reconcile，只读派生，不存储）
对每个绑定：是否已是主线祖先、是否已是集成分支祖先、领先/落后提交数、`merge-tree` 试合冲突文件、工作区是否脏（带超时→"未知"）、是否已推送、PR 状态、会话最后活动时间与状态摘要。

### 合并单（Release Plan，可保存可重跑）
一次"合并 vX"的计划与执行记录：顺序、每条的预检结果、用户勾选（并入 / 不并 / 待定）、执行日志、冲突处理方式、顺延清单。等价于用户现在手写的《总分支合并与重构方案》勾选表，但可执行。

## 5. 看板信息架构（中文、小白可懂）
- **顶部健康条**：主线落后远端 / 领先；集成分支未并回主线 N 天；未推送分支数；脏 worktree 数。
- **版本列**（左→右：v1.2 待办 / v1.3 规划 / 以后）：每列顶部"还欠 N 项"，列内功能卡。
- **功能卡**：名字、所在仓库与分支（随机分支名自动配可读标签）、状态灯（绿=可合、黄=落后需同步、红=试合冲突、灰=无动静、紫=等你回答）、最后活动、一键动作（同步基线 / 预约改期 / 打开会话）。
- **合并抽屉**："合并 v1.2" 的预演：按顺序列出每条预检结果与冲突文件，勾选后执行，执行中逐条打钩，结尾给发布说明草稿与顺延清单。
- **卫生页**：待清理 worktree、目录名≠分支名、孤儿条目、手工拷贝疑似项。

## 6. 调用面
- **MCP server（stdio）**：`heliu.status / feature.add / feature.reserve / milestone.todo / release.preview / release.run / branch.sync / hygiene.scan`。任何 Claude / Codex 会话都能用一句话触发。
- **CLI**：同一套动词，中文友好的 `heliu 待办 1.2` 与英文别名并存；输出表格或 JSON。
- **Skill**：`/heliu` 在主控会话里完成"按版本给会话分组、开新会话、合并"等需要桌面应用自带工具（list_sessions、start_session、sync_with_base_branch）的动作。
- **Hooks（零额外动作）**：SessionStart 注入"你在 X 分支，对应功能 Y，预约 vZ，落后主线 N"；Stop/SessionEnd 回写最后活动与状态摘要；WorktreeCreate 自动建功能卡草稿。
- **看板**：本机 `localhost` 网页（任何浏览器、Codex 也能看）；二期做桌面应用 mod pane。

## 7. 非目标
不做多人协作与权限；不替代 GitHub/GitLab；**不自动 push、不自动建 PR、不自动删分支或目录**；不改用户的分支命名；不在 iCloud 目录放数据库；不写 Obsidian 的 `- [ ]` 复选框。

## 8. 数据落点
- **台账（承诺）**：每个仓库根目录 `.heliu/`（`milestones.yaml`、`features.yaml`、`releases/vX.md`），纯文本、可提交、人可读；多仓库项目在"主仓库"（文档仓）里用 `project.yaml` 挂其他仓库路径。
- **索引缓存（事实）**：`~/Library/Application Support/heliu/<project-id>/cache.sqlite`，可随时删除重建，绝不放 iCloud。
- **桌面应用会话数据**：只读解析 `claude-code-sessions/*/local_*.json` 与 `git-worktrees.json`，容错缺字段。

## 9. 怎么算做成（验收口径，用户体验式）
1. 打开看板 10 秒内看懂：磁吸背夹 v1.2 还欠哪几项、哪几项能合、哪几项在等我。
2. 新开一个会话随口说"做个 X"，不做任何额外动作，看板上出现 X 的卡片并预约到下一版。
3. 说"合并 v1.2"，先看到预演（顺序、冲突、顺延），确认后合完，发布说明和顺延清单自动生成。
4. 一条老分支，能一眼看出落后主线多少，并一键同步基线。
5. 全程没有一次自动 push / 删除；iCloud 仓库扫描不卡死（超时标"未知"）。
6. ChatGPT（Codex）以普通用户视角走完上述 5 条，给出"能解决问题 / 不能"的结论；最多 3 轮。
